# Context 검색 검토 질문과 근거

이 답변은 2026-10-06의 최종 기록에 근거합니다. 공개 숫자는 [검증 요약](context_validation_20261006.md)과 [모든 전후 순위](context_validation_queries_20261006.csv)에 있습니다. 실제 질의·정답·사실·출처는 팀 내부 HTML/Excel에서 확인합니다.

| 검토 질문 | 확인한 답변 | 직접 볼 자료 |
|---|---|---|
| 기존 검색에 실제로 합쳐졌는가? | 후보 절단 전에 Context를 한 경로로 연결했습니다. 실제 API의 정답 후보 진입과 양수 Context 기여, 거절 후 30개 후보 보충을 확인했습니다. | 내부 API18건의 Context/후보 보충 응답 |
| 분석이 달라져서 좋아진 것 아닌가? | OFF/ON 한 쌍에 같은 분석·코퍼스·후보 폭·rerank OFF를 사용했습니다. API의 새로운 분석은 paired 효과 계산에 섞지 않았습니다. | 각 phase의 analysis/arm_order/cache 및 해시 |
| 성공한 질문만 골랐는가? | 166개 전체를 보고합니다. 실패·불변·후보 하락도 포함합니다. 반복10/API18을 새 독립 질의로 더하지 않았습니다. | 내부 모든질의166 시트와 공개166행 CSV |
| 이미지 가중치만 양수이고 실제 조회는 없는 것 아닌가? | 이미지 필수 dev9/test3/작성6의 OFF/ON 임베딩·조회를 확인했습니다. 실제 API 이미지7건은 요청 ID와 같은 작업의 embed/query를 연결했습니다. | API 상세의 span ID/parent/job/run, required_path_verified |
| 오디오도 실제로 동작하는가? | 작성셋 필수6개가 OFF/ON 실행됐고 실제 API8건이 실행됐습니다. Top-10 오디오 양수 기여는2건입니다. 실행만으로 오디오 단독 정확도를 주장하지 않습니다. | API의 실행/Top-10 기여를 구분한 열 |
| 무관한 사실을 근거로 보여주지 않는가? | Dense 사실의 곡 귀속·질의 관련 사건을 확인한 경우만 표시합니다. 주평가 표시28건은 등록 라벨 일치, 미검토0입니다. Sparse 일치를 사실 증거로 표시하지 않습니다. | 내부 표시근거32회 시트: 주평가28/반복2/API2 구분 |
| 근거를 안 보여준 정답은 실패 아닌가? | 검색 정확도와 근거 제공을 구분합니다. 관련 사실을 충분히 확인하지 못하면 표시를 억제합니다. 근거 제공률100%라는 주장은 하지 않습니다. | on_top10_rank와 target_evidence_record_id/표시 사실 |
| 사실이 많은 곡이 점수를 여러 번 받는가? | Dense 사실은 song_id별 최고 점수로 집계합니다. Dense/Sparse 내부 RRF 뒤 하나의 Context 경로로 합류해 점수 합산과 경로 중복 가산을 막습니다. 사실 수에 따른 검색 기회 편향 전체가 사라졌다고 주장하지 않습니다. | 집계/RRF/router 구현과 합성 테스트 |
| Context가 없는 곡은 감점되는가? | 별도 감점하지 않습니다. 다른 후보의 추가 기여로 개별 순위는 움직입니다. 보호한 적중률/MRR 하락은 관찰되지 않았고 후보 순위 하락3건도 남겼습니다. | 보호 지표 표와 후보 하락 필터 |
| 3016곡 처리인데 프로필은 왜478개인가? | 문서 없음1846/여담 없음692도 처리 완료입니다. 검색 가능한478곡에서 사실3995개/프로필478개를 생성했습니다. complete는 모든 곡에 벡터가 있다는 뜻이 아닙니다. | corpus_identity와 Context manifest |
| 최종 활성 인덱스를 사용했는가? | 완성 build와 Dense/Sparse 활성 generation이 일치하는 코퍼스 정체성을 phase들에서 확인했습니다. 이전 generation 폴더의 존재만으로 현재 사용 중이라고 판단하지 않습니다. | corpus_identity와 등록 코퍼스 해시 |
| 블라인드 평가인가? | 최종 재검사는 관찰한 질의의 후속 회귀 검사입니다. 작성 질의셋도 결과를 보고 수정에 활용했습니다. 새 블라인드/실사용자 표본으로 설명하지 않습니다. | 등록 inventory/설정·소스 해시/한계 |
| 모든 사람의 질문을 커버하는가? | 여러 작품/제작/공연/밈/MV/버전/음악 요소와 가사·소리·이미지·무관 대조를 검사했습니다. 작성 배경질의7/36과 dev4/18은 여전히 Top-10에 없습니다. | 미진입 필터와 모든 원문 |
| 왜 top_k=10인가? | 제품 화면의 고정값입니다. 최적 표시 크기로 검증한 값은 아닙니다. 후보30과 표시10을 구분합니다. | 등록 setting과 비교 조건 |
| rerank를 켜도 같은가? | 이 자료는 OFF 조건입니다. 일반 UI의 ON 정확도·지연은 이 결과로 확대해서 설명하지 않습니다. | request.use_rerank=false, rerank span 없음 |
| 나무위키 사실 자체가 참임을 검증했는가? | 저장된 문장과 질의 관련성·곡 귀속을 대조했습니다. 원문 사실의 독립적 진실성 인증은 아닙니다. | 등록 리뷰의 basis와 출처 |
| push하면 팀원도 같은 검색을 쓰는가? | 코드만으로는 부족합니다. 현재 Qdrant는 로컬이므로 같은 코퍼스·artifact·BM25·모델·인덱스·환경을 내부 배포로 맞춰야 합니다. | 데이터 배포 README와 코퍼스 정체성 |
| .env에 Context1.0을 복사해야 했는가? | 현재 factory가 명시 측정값 .5/2/100/100/30을 전달합니다. .env에 추가하지 않아도 검증은 유효했습니다. 예시 문서는 측정값으로 맞추고, 환경변수만으로 runtime이 바뀐다고 설명하지 않습니다. | dependencies.py factory와 activation.router_arguments |
| 콘솔에 옛 실패 또는 note에 API 확인 필요라고 쓰여 있는데 완료인가? | 콘솔은 과거 실행이 이어 붙을 수 있습니다. 적용 때 쓴 초기 note는 남지만, 최종 API 상태 passed_api_smoke·api_verified=true와 연결된 SHA/시각을 기준으로 확인합니다. 원본 기록을 바꿔 실패를 지우지 않았습니다. | 최종 activation/API JSON과 capture_info의 마지막 child_exit=0 |
| explain의 기여 가중치와 설정 .5가 다를 수 있는가? | .5는 기본 Context 값입니다. 질의 신뢰도·이름 있는 작품의 보정을 적용한 실제 기여와 구분합니다. 개별 응답 explain과 해당 Context 경로 구현에서 실제 계산을 확인할 수 있습니다. | 내부 API의 explain.paths/detail과 context_route 구현 |
| 숫자를 다시 확인할 수 있는가? | 읽기 전용 도구가 SHA 연결,166행의 순위·분모·공개 CSV와 HTTP ID/원문/미디어 시간 구간을 교차 확인합니다. 새 검색은 수행하지 않습니다. | check_context_release_evidence.py |

검토자가 판단할 근거와 해석 범위를 제시한 자료입니다. 코멘트가 전혀 생기지 않는다는 보증이나 모든 사용자 문장의 성공을 주장하는 자료로 쓰지 않습니다.
