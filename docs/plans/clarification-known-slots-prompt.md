재질문에서 사용자가 처음부터 알려준 성별·장르를 다시 묻는 문제를 수정해줘.
계획서는 `docs/plans/clarification-known-slots-plan.md`에 있어. 먼저 읽고 현재 코드와 대조한 뒤 구현과 검증까지 진행해줘.

재현 사례와 원하는 동작:

1. `중학생 때 나온 엄청 유명한 남자 아이돌 노래`
   - 성별을 다시 묻지 않는다.
   - 필요한 출생 연도 질문은 유지한다. 연도 답 또는 건너뛰기 뒤에도 성별은 제외한다.
   - 장르를 아직 모르고 후보를 구분하는 데 도움이 되면 장르 질문은 가능하다.
2. `남자 인디 노래인데 뮤비에 의자가 하늘에 떠있는 장면이 있어`
   - 성별과 현재의 일반적인 장르 질문을 모두 하지 않는다.
   - 물을 항목이 없으면 `이 중에는 없어요`를 눌렀을 때 질문 없이 다음 후보를 찾는다.

확인된 원인:

- `clarify.py`는 과거 오기억 실험 때문에 이미 명시한 슬롯도 다시 묻는 정책이다. `test_asks_again_even_when_the_user_already_said_it`이 그 동작을 고정하고 있다.
- `pick_data_question()`은 후보와 asked_slots만 본다. `/search/clarify`에는 원문에서 알려준 정보가 전달되지 않는다.
- rule_fallback에서는 두 예시 모두 vocal_gender=None, genre=""이므로 분석 필드만 검사하는 수정으로는 부족하다.

구현 요구사항:

- 최초 질의에서 명시한 데이터 항목을 재질문 전용 `known_slots`로 계산해줘. 원문 근거를 확인하고, 모델 추론값이나 단순 부분 문자열만으로 확정하지 마.
- `known_slots`와 실제 질문 이력인 `asked_slots`를 분리해줘. 가짜 answers를 만들거나 질문·턴 한도를 소비하면 안 돼.
- SearchResponse → map.js의 대화 상태 → ClarifyRequest로 known_slots를 전달해줘. 허용 값은 vocal_gender와 genre뿐이고 기본은 빈 목록이다. 질문 조회에서 원문 재분석이나 추가 모델 호출은 하지 마.
- 즉시 질문, 지연 질문, clarify_deferred 판단, 재질문 평가 하네스에 같은 제외 규칙을 적용해줘. 두 데이터 슬롯을 모두 알면 deferred=false, 직접 질문 조회도 null이며 후보 fetch를 생략해야 한다.
- `인디`는 현재의 넓은 장르 질문을 제외할 근거로 처리하되 검색용 genre를 임의로 바꾸지 마. 검색 분석값·프롬프트·검색 점수·후보 생성은 유지해줘.
- 출생 연도 답 이후에는 최신 후보와 known_slots를 사용하고, 새 검색에서는 이전 단서와 질문 캐시가 남지 않게 해줘. 기존 중복 클릭·늦은 응답·조회 실패 시 거절 진행 보호는 유지해줘.
- demo_rehearsal, 모의 서버 왕복, 프론트 테스트 등 질문 조회 호출부를 함께 갱신하고 map.js 캐시 버전도 올려줘.
- 이전 재질문 정책의 테스트와 주석을 새 요구사항으로 교체해줘. 테스트의 기본 original_query에 `발라드`가 들어 있어 장르 미지정 테스트와 충돌할 수 있으니 fixture도 확인해줘.

검증 기준:

- 위 두 사례를 정상 분석과 성별·장르 필드가 빈 분석 모두에서 검증해줘.
- 단서가 없는 질의는 기존 질문이 가능하고, 하나만 아는 경우에는 나머지 항목을 물을 수 있어야 한다.
- `뮤비에 남자가 나와`, 가사·제목·아티스트명에 든 단어, `인디아나` 같은 부분 문자열을 보컬 성별·장르로 오인하면 안 된다.
- `남자인지 모르겠어`, `남자일 수도 있어`, `여자는 아니야`, `인디는 아니고 장르는 모르겠어`를 확정 정보로 처리하지 마.
- `남자 보컬이고 장르는 모르겠어`는 성별만 유지하고, `장르는 '인디'야`는 장르 단서로 인정해줘. 부정·영상·따옴표 처리가 문장 전체의 유효한 단서를 지우지 않도록 해줘.
- 출생 연도 답/건너뛰기, 새 검색 초기화, null일 때 거절 검색 1회, 실패·늦은 응답을 테스트해줘. API 응답부터 질문 요청까지 새 필드가 실제로 전달되는 왕복도 검증해줘.
- 계획서의 관련 pytest 묶음과 전체 pytest를 실행하고 결과를 보고해줘. 모델·실제 DB 없는 테스트부터 진행해줘.

과거 오기억 평가의 일부 회수율이 내려갈 수는 있어. 그 점은 별도 보고하고, 기존 평가 숫자를 맞추려고 이미 말한 항목을 다시 묻는 동작을 넣지는 마. 이번 목표는 사용자에게 받은 정보를 기억하고 필요한 것만 묻는 거야.

커밋·푸시·PR 생성은 하지 마. 연도 휠 UI, 으르렁 유명도 보충, 크롤러·코퍼스·색인은 건드리지 마.
완료 후 변경 파일, 두 사례의 실제 질문 결과, 테스트 결과, 남은 제약을 정리해줘.
