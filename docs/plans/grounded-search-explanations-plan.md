검색 설명의 허구 주장 노출 방지와 미확인 MV 장면 질의 처리 계획

작성일: 2026-10-11. 코드·로컬 데이터 검토 및 모의 응답 검증을 바탕으로 작성했다. 이 문서 작성 과정에서는 서비스 코드, 데이터, 색인을 수정하지 않았다.

1. 문제와 판단

사용자 질의: `남자 인디 노래인데 뮤비에 의자가 하늘에 떠있는 장면이 있어`

사용자 관찰: BOYNEXTDOOR의 `Upside Down`이 1위이고, 근거 패널 마지막에 `뮤직비디오에 옥상에서 의자를 던지는 장면이 나온다`는 문장이 표시됐다. 사용자는 해당 장면이 없다고 확인했다.

판단: 출처가 확인되지 않은 구체적인 장면을 곡의 사실처럼 표시할 수 있는 실질적인 결함이다. 현재 경고 문구가 있지만 허구 주장을 차단하지 않는다. 순위도 같은 모델의 결과를 사용하므로 설명 노출과 순위 판단을 함께 점검해야 한다.

다만 다음을 구분한다.

- **확인됨:** 해당 곡의 현재 로컬 수집 레코드에는 의자 장면이 없다. 원본 레코드로 재구성한 리랭커 입력에도 없다. 임의의 장면 문장이 모델 응답에 들어오면 파서와 API 출력이 그대로 통과시킨다.
- **가능성:** 가사 요약의 옥상과 사용자가 말한 의자 장면을 모델이 결합했을 수 있다. 실제 모델의 내부 판단으로 입증한 것은 아니다.
- **미확인:** 사용자가 봤던 정확한 요청의 후보 순서·분석·모델 원문이 확보되지 않아, 그 장면 주장 때문에 실제 1위가 됐다고 단정할 수 없다. 영상 전체를 직접 시청해 모든 판본에서 장면이 없음을 입증한 것도 아니다.

코퍼스에 연결된 YouTube 주소는 `https://www.youtube.com/watch?v=86NUEhixJlk`이다. [공식 아티스트 채널의 해당 페이지](https://www.youtube.com/watch?v=86NUEhixJlk)는 KOZ가 제공한 자동 생성 음원 업로드로 설명된다. 이 URL이 있다는 사실만으로 MV 장면이 확인된 것은 아니다. 다른 MV 판본의 존재·부재는 별도 확인 사항이다.

현재 코드 기본값과 로컬 설정에서는 `GEMINI_RERANK_USE_SEARCH`와 `GEMINI_RERANK_RARE_FACT_VERIFY`가 꺼져 있다. 실행 중인 서버의 환경까지 확인한 것은 아니다. 또한 `_rare_fact_reason()`에 사용자 예시를 넣으면 빈 문자열이 나온다. 희소 사실 검증 스위치만 켜도 이 예시가 검증되는 구조가 아니다.

로컬 검증:

- 해당 원본 레코드로 만든 `_candidate_payload()`에 옥상은 있고 의자는 없었다. 실행 중인 Qdrant의 실제 payload를 읽은 결과는 아니다.
- 보고된 문장을 넣은 **모의** 모델 응답을 `_parse_response()`와 `to_track_explain()`으로 처리하자 `model_notes`에 그대로 남았다. 실제 Gemini가 같은 문장을 새로 생성했다는 의미는 아니다.
- 결정적 `summary`에는 그 문장이 섞이지 않았다. 기존 분리 장치는 작동하지만 일반 사용자에게 미검증 문장을 노출한다는 문제가 남는다.
- 기존 테스트 `test_parse_response_keeps_the_model_reason`, `test_track_explain_labels_the_model_note_as_unverified` 두 건 통과.

3. 수정 범위와 원칙

이번 작업은 **사용자에게 표시하는 사실 주장**과 **자료 없이 장면을 추측하는 재정렬**을 각각 막는다.

- 현재 실행 기록에서 만든 순위·검색 경로 설명과 실제 가사 인용은 유지한다.
- 자유 생성한 `reason`을 확인된 음악 사실이나 실제 내부 인과 설명으로 취급하지 않는다.
- 정보 없음은 `미확인`이다. 장면이 없다는 판정, 후보 제외, 반대 사실의 증거로 바꾸지 않는다.
- 가사 속 장면, 창작한 분위기 이미지, 앨범 표지, MV 장면은 구분한다. 원문에 같은 단어가 있다는 이유만으로 서로의 증거로 승격하지 않는다.
- Upside Down을 ID로 차단하거나 순위를 고정하지 않는다. 특정 문구만 지우는 필터도 만들지 않는다.
- 전체 질의에서 일반 지식을 한꺼번에 금지하거나, 외부 검색·희소 검증을 전역으로 켜지 않는다. 변경 범위와 회귀 영향을 제한한다.

4. 1단계 — 설명 노출을 실제 기록으로 제한

- 일반 검색 API와 사용자 화면에서 자유 생성 `model_notes`를 기본 설명으로 내보내지 않는다. 경고 추가나 CSS로 숨기는 것만으로 끝내지 않는다.
- 내부 `RerankRun`·실험 진단 기록에는 원문을 보존한다. 원인 추적에 필요한 기록까지 파서에서 삭제하지 않는다. 일반 API에서 진단 노출을 켜는 새 옵션을 추가할 필요는 없다.
- 응답 호환성을 위해 공개 `model_notes` 필드를 빈 배열로 남길 수 있다. 이 경우 프론트와 API 테스트에 계약을 명시한다.
- `render_ko()`의 실행 기록 설명과 `evidence`의 검증된 가사 인용은 유지한다. 과거 설명이 새 결과에 남는지도 테스트한다.
- MV 장면을 판단할 자료가 없는 요청에는 서버의 구조화된 상태로 다음과 같은 안내를 제공한다: `말씀하신 뮤직비디오 장면은 확인할 자료가 없어, 다른 단서로 찾은 후보를 보여드려요.` UI 문장을 LLM이 생성하게 하지 않는다.
- 이 단계만 적용했을 때 검색 결과의 ID·순서·점수는 같아야 한다. 설명 노출 수정과 다음 단계의 순위 정책 효과를 분리한다.

5. 2단계 — MV 장면 근거가 없는 질의의 보수적 처리

추천하는 첫 구현은 **구체적인 MV 장면을 요청했으나 그 장면을 평가할 출처 자료가 리랭커에 없는 요청에 한해 Gemini 재정렬을 건너뛰는 것**이다. 모델에게 더 조심하라고 지시하는 것보다 적용 범위와 동작을 검증하기 쉽다. 검색은 계속하고, 기존 검색·명시 보정으로 얻은 후보 순서를 유지한다.

- 질의 판정은 공통 함수로 만든다. 원문에서 `뮤비/뮤직비디오/MV`와 구체적인 시각 장면의 관계를 확인한다. 단순히 MV라는 글자가 있다는 이유로 켜지지 않도록 한다.
- `의자가 하늘에 떠 있는 뮤비`, `뮤직비디오에서 의자를 던져`, `MV에 사람이 거꾸로 매달린 장면`은 대상이다.
- `뮤비가 유명한 노래`, `의자가 떠 있는 것 같은 몽환적인 분위기`, `가사에 '뮤비에서 의자를 던져'라는 말이 있어`, `뮤비는 기억 안 나고 남자 발라드야` 등은 구분한다. 반례의 구체적인 지원 범위를 테스트와 문서로 남긴다.
- 분석 프롬프트는 유지한다. 최초 분석·fallback·prior_analysis 재검색에서 동일한 원문 판정을 사용한다.
- 현재 후보 입력에는 장면별 출처 계약이 없다. 모델이 `support=0.99`라고 말하거나 `verified=true`를 생성한 것을 자료가 있는 상태로 인정하지 않는다. 임의의 YouTube 링크, 가사 요약, `visual_imagery`도 인정하지 않는다.
- 이번 구현에서는 없는 증거 시스템을 새로 구축하지 않는다. 이미 연결 가능한 출처 자료가 발견되면 노래·판본·주장과 연결되는지 먼저 점검한다. 관련 없는 `music_video` 사실 하나로 요청 전체의 제한을 해제하지 않는다.
- 보호 정책은 Gemini 백엔드에 한정한다. Cross-Encoder 등 다른 백엔드까지 암묵적으로 바꾸지 않는다.
- 재정렬 호출 전에 판단해 추가 Gemini 호출 없이 처리한다. 해당 상태를 `failed`나 `applied`로 기록하지 않고, 의도적 생략과 그 이유를 남긴다. 없는 `score_mix`, 모델 순위 이동, 모델 이유를 생성하지 않는다.
- 유지할 순서는 현재 요청의 답변 보정·거절 제외까지 반영된 후보 순서다. 리랭커 입력용으로 따로 만든 보정 전 순서로 되돌아가면 안 된다.
- 기존 가사 일치 보호·동일 가사 후보 정렬의 의미가 깨지지 않도록 확인한다. MVP 범위를 넘어가는 혼합 단서의 세밀한 최적화는 별도 실험으로 둔다.
- `search_router.py`와 `evaluate_search_accuracy.py`는 이미지 질의 생략 판단도 공유한다. 새 정책 역시 서비스·평가가 같은 함수를 사용하게 한다. 직접 리랭커를 호출하는 도구도 찾아 의도한 범위를 명시한다.

이 방어책은 의미 검색 후보 자체의 오류까지 해결하지는 않는다. `visual_imagery`가 텍스트 passage에 들어가는 현재 구조에서는 상상 장면이 후보 생성에 영향을 줄 수 있다. 이번 범위에서 색인 전체를 바꾸지 않고 그 한계를 기록한다. 재정렬을 생략해도 Upside Down이 상위에 남을 수 있으며, 특정 곡이 1위에서 사라졌는지를 유일한 성공 기준으로 삼지 않는다.

6. 출처 기반 장면 판단은 후속 확장

향후 실제 MV 장면을 검색·설명하려면 해당 곡·영상 판본에 연결되는 자료가 필요하다. 영상 관찰이라면 URL·타임스탬프·관찰 내용, 문서 인용이라면 URL·문서 버전·인용 구간·주장 범위를 보존한다. 문서에 적혀 있다는 것과 영상에서 직접 확인했다는 것도 구분한다.

모델이 새로운 출처를 만들어 내게 하지 말고 서버가 제공한 evidence ID를 선택하게 한다. 서버는 후보 ID, 자료 종류, 원문 구간, 버전 일치를 확인해야 한다. 인용문이 원문에 존재한다는 검증만으로 그 인용이 주장 전체를 뒷받침한다고 단정해서는 안 된다. 특히 가사의 옥상 인용은 MV 의자 장면을 뒷받침하지 않는다.

현재 나무위키 Context에는 `music_video` 분류와 출처 관련 구조가 있다. 이를 재사용할 가능성은 있지만 현재 리랭커 입력과 연결된 장면 검증 계약으로 보아서는 안 된다. 이번 수정에서 크롤링·영상 분석·색인 재생성을 필수 작업으로 만들지 않는다.

7. 검증 계획

외부 모델·DB 없는 테스트부터 수행한다.

| 영역 | 통과 기준 |
| --- | --- |
| 허구 응답 | 모의 모델이 높은 confidence와 함께 의자 장면을 반환해도 일반 API·UI에는 사실 설명으로 표시되지 않음. 내부 진단 원문은 유지. |
| 임의 주장 | 문제 문장 외의 허구 인물·장소·소품 주장도 동일하게 처리. 문자열 하나에 맞춘 차단이 아님. |
| 기존 근거 | 검색 경로·점수·순위 기록과 실제 가사 인용 유지. 설명 노출만 바꾸면 결과 ID·점수가 동일. |
| 입력 종류 | 가사 요약·창작 이미지·단순 URL을 MV 장면 확인으로 취급하지 않음. |
| MV 보호 | 사용자 예시와 표현 변형에서 Gemini 호출 없이 정책 생략 상태, 후보·답변 보정 순서 유지. |
| 비대상 | 일반 성별·장르·가사·감성·제목 질의와 위 반례에서는 불필요한 생략 없음. 기존 이미지 정책과 공존. |
| 상태 | 실패와 의도적 생략을 구분. 생략한 결과에 리랭커가 판단했다는 문장·이전 모델 이유·점수 혼합 기록이 남지 않음. |
| 경로 일치 | API 검색과 정확도 평가 도구의 보호 정책 일치. prior_analysis 재검색에서도 유지. |
| 프론트 | 원시 모델 이유를 포함한 구형 응답을 받아도 근거로 표시하지 않음. 안내와 검증된 기록은 정상 표시. |

우선 실행할 테스트는 `test_gemini_listwise_reranker.py`, `test_search_explain.py`, `test_lyric_evidence.py`, `test_router_rerank_input_order.py` 및 새 정책·프론트 테스트다. 이어서 전체 pytest를 한 번 실행하고 기존 실패와 신규 실패를 구분한다. 모델 호출을 금지한 테스트로 정책 생략을 확인한다.

순위 정책은 품질과 교환 관계가 있다. 효과 측정에서는 다음을 지킨다.

- 당시 원본 응답이 있으면 보존한다. 없으면 재실행을 별도 관찰로 기록하고 과거 실행을 재현했다고 쓰지 않는다.
- 현재 5,143곡의 동일 코드·분석 캐시·후보 ID·후보 입력 순서·설정으로 비교한다. 사용자 사례는 정답 라벨이 없으므로 Hit@1 성공/실패를 임의로 매기지 않는다.
- 먼저 해당 사례와 기존 dev의 MV 장면 질의, 대표 비대상 질의를 비교한다. 실제 모델이 필요한 비교는 이전 정책의 변동을 확인할 수 있게 반복하고 원문·입력·설정 해시를 보존한다. 새 보호 경로는 추가 모델 호출이 없어야 한다.
- 결과에는 후보 단계 순위, 최종 순위, 모델 생략 이유, 미확인 장면 주장 노출 수, 호출 수·지연 시간을 기록한다. 정답 라벨이 있는 dev는 Hit@1/10도 함께 본다.
- 비대상 질의까지 리랭커 프롬프트를 바꾸는 등 범위가 넓어지면 기존 dev 116건 회귀 측정이 필요하다. 기존 기준선 파일을 덮어쓰지 않는다. 봉인 test는 사용하지 않는다.
- 사용 중인 로컬 Qdrant를 별도 프로세스로 열거나 재생성하지 않는다. 실물 검증이 필요하면 제공된 실행 환경과 기존 격리 방식에 맞춘다.

8. 완료 보고

보고에는 확인된 원인과 추정, 수정 파일, 일반 응답에서 제거한 노출 경로, 생략 정책 범위, 로컬 테스트·실제 측정 결과, 수행하지 못한 검증, 검색 품질의 교환 관계를 적는다. `환각이 완전히 없어졌다`, `정답을 찾았다`, `모든 MV에 장면이 없다`고 주장하지 않는다.

커밋·푸시·PR 생성은 하지 않는다. 이미 병합된 재질문 정책, 연도 휠 UI, 유명도 보충, 크롤러·코퍼스·임베딩·색인은 이번 작업에서 변경하지 않는다.
