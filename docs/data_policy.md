# 수집 데이터 이용 범위 — 저작권·초상권

> 멘토님 권고("수집 데이터의 저작권·초상권 이슈는 학술 목적 임베딩 활용으로 범위를 한정한 점을
> 명확히 문서화해 향후 시연·발표 시 근거로 활용")에 따라, 팀이 수집 데이터를 **어디까지, 무엇에**
> 쓰는지 정리한다. 팀의 운영 기준이며 **법률 자문을 받은 판단은 아니다.**

## 요약

> 수집한 가사·음원·앨범 커버·댓글은 학술 연구용 검색 모델의 **임베딩(수치 벡터) 생성과 색인에만**
> 쓰고, 원본 데이터셋은 **외부에 배포하지 않는다.** 공개 저장소에는 코드만 있고, 시연 화면은
> 음원과 이미지를 직접 호스팅하지 않는다.

1. **목적 한정** — 졸업 작품 연구용 프로토타입이다. 상업 서비스로 운영하지 않는다.
2. **용도 한정** — 수집 데이터는 임베딩·색인 생성, 검색 품질 평가, 팀 시연에만 쓴다.
3. **배포 안 함** — 원본(가사 전문·음원·커버·댓글)과 그 파생물(임베딩 벡터, 곡 목록)은 공개하지 않는다.
4. **노출 최소화** — 화면은 원본 대신 YouTube 임베드와 원본 이미지 주소를 쓰고, 가사는 근거가 되는 한 줄만 보여 준다.

## 1. 무엇을 모으고 어디에 쓰는가

| 데이터 | 출처 | 관련 권리 | 쓰는 곳 | 공개 저장소 | 시연 화면 |
|---|---|---|---|---|---|
| 곡 정보 (제목·가수·앨범·발매일·장르) | 멜론 | 사실 정보 | 검색 필터, 결과 표시 | 없음 (곡 목록 파일 제외) | 표시 |
| 가사 전문 | 멜론 | 저작권 (작사) | BM25 색인, 가사 정확 일치 검색, LLM 요약 입력 | 없음 | **질의와 일치한 구절이 든 한 줄만** 근거로 인용. 전문은 보여 주지 않는다 |
| 앨범 소개문 | 멜론 | 저작권 | LLM 요약 입력 | 없음 | 표시 안 함 |
| 앨범 커버 이미지 | 멜론 | 저작권, **초상권** (인물 사진) | SigLIP2 이미지 임베딩, 평가 라벨 확인(팀 내부) | 없음 | 원본 CDN 주소를 참조해 표시. 서버가 사본을 내보내지 않는다 |
| 음원 (`audio.m4a`) | YouTube | 저작권, 저작인접권 | CLAP 오디오 임베딩 | 없음 | **재생하지 않는다.** 듣기는 YouTube 임베드 플레이어로 연결 |
| 댓글 | 멜론, YouTube | 작성자 저작권, 개인정보 | LLM이 반응 요약·팬 태그를 만드는 입력 | 없음 | 원문 표시 안 함 |
| 나무위키 사실 | 나무위키 | CC BY-NC-SA 2.0 KR | 배경지식 검색 (아직 API 검색 후보 결합에 연결됨) | 없음 | — |
| LLM 생성 요약·태그 | Gemini가 위 데이터로 생성 | 원문의 파생물 | 텍스트 임베딩, 리랭커 입력 | 없음 | 선정 근거 설명에 일부 |

- 댓글은 **본문만** 저장한다. 작성자 이름·계정은 저장하지 않는다.
- 나무위키 사실에는 출처 URL을 함께 보관한다.
- 임베딩은 원문을 수치 벡터로 바꾼 것이다. 벡터에서 원문을 되살리는 기능은 없고, 검색은 벡터 간 유사도로만 한다.

## 2. 저장과 접근

| 무엇 | 어디 | 접근 |
|---|---|---|
| 곡 폴더 원본 (`meta.json` · `audio.m4a` · `cover.jpg`) | 팀 Google Drive | 팀원 |
| 가사·메타데이터 | MongoDB Atlas | 팀 계정 |
| 임베딩 벡터 | 팀 Google Drive, 각자 로컬 Qdrant (`artifacts/`) | 팀원 |

- **외부 처리**: 수집 데이터 정제(요약·태그 생성)와 검색 질의 분석에 Google Gemini API를 쓴다.
  정제 단계에서 가사·앨범 소개문·댓글 일부가 가공을 위해 API로 전송된다.

## 3. 공개 저장소에 원본이 없다는 근거

| 근거 | 위치 |
|---|---|
| 데이터 폴더·산출물·곡 목록을 추적하지 않는다 | `.gitignore` (`data/`, `artifacts/*`, `*.csv`, `src/frontend/static/map_data.json`) |
| 공개 전환 때 **과거 히스토리 없이** 새로 시작했다. 옛 커밋에 있던 음원·가사·임베딩이 공개 저장소에 없다 | 2026-09-28, 첫 커밋 `5e0e23f` |
| 공개 전에 추적 파일을 실제 가사·앨범 소개문·댓글과 대조했다. 남은 일치는 곡 제목과 같은 문장과 데모 질의 한 줄뿐이다 | 2026-09-28 점검 |
| 테스트 데이터의 가사·소개문·댓글을 가상 문장으로 바꿨다 | `tests/context/fixtures/` |
| README 시연 GIF는 앨범 커버를 흐리게 처리했다 | `docs/images/map_demo.gif` |

공개 저장소에 들어 있는 파생물은 두 가지다.
- `artifacts/bm25_params.json` — 해시된 단어 ID와 문서 빈도뿐이라 가사를 되살릴 수 없다
- 평가 질의 세트 — 팀이 직접 쓴 문장이다. 기억나는 가사 몇 어절을 인용한 질의가 3건 있다

## 4. 시연·발표 기준

- 시연은 팀이 운영하는 환경에서 한다. 불특정 다수가 접속하는 공개 서비스로 열지 않는다.
- 발표 자료·영상에 넣는 앨범 커버는 흐리게 하거나 작게 쓴다.
- 가사는 근거로 한두 줄만 인용한다. 전문을 화면에 띄우지 않는다.
- 음원은 YouTube 임베드로만 재생한다. 수집한 음원 파일을 틀지 않는다.
- 권리자나 당사자가 삭제를 요청하면 해당 곡을 드라이브·MongoDB·Qdrant·임베딩에서 지운다.

## 5. FAQ

**Q. 가사를 모았는데 저작권 문제는 없나요?**
A. 가사는 검색용 색인과 임베딩을 만드는 데만 쓰고 배포하지 않습니다. 화면에는 사용자가 입력한
구절과 일치한 한 줄만 근거로 보여 주고, 공개 저장소에는 가사가 없습니다.

**Q. 앨범 커버에 가수 얼굴이 있는데 초상권은요?**
A. 커버는 이미지 분위기를 벡터로 바꾸는 데만 쓰고, 파일을 공개하거나 서버에서 내보내지 않습니다.
화면에는 원본 주소를 참조해 보여 주며, 공개 자료에서는 흐리게 처리했습니다. 얼굴 인식은 하지 않습니다.

**Q. 음원을 내려받았나요?**
A. 오디오 임베딩(소리 특징 벡터)을 만들기 위해 받았고, 팀 드라이브와 팀원 작업 환경에만 있습니다. 서비스에서 재생은
YouTube 임베드로 원래 영상을 트는 방식이라 음원을 다시 배포하지 않습니다.

**Q. 댓글은 개인정보 아닌가요?**
A. 작성자 이름·계정은 저장하지 않고 본문만 저장합니다. 원문을 화면에 보여 주지 않고, LLM이 만든
반응 요약만 검색에 씁니다.

**Q. 공개 저장소에 데이터가 들어 있지 않나요?**
A. 코드만 있습니다. 공개 전환 때 과거 히스토리 없이 새로 시작했고, 추적 파일을 실제 가사·댓글과
대조해 확인했습니다(3장).

## 6. 이 문서의 한계

- **법률 자문을 받은 판단이 아니다.** 학술 목적이라도 저작권법상 허용 여부는 사안마다 따로 판단해야 한다.
- 데이터를 모은 방법(각 사이트 이용약관 준수 여부)은 이 문서의 범위가 아니며, 별도 검토가 필요하다.
- 시연 화면에는 앨범 커버(원본 주소 참조)와 가사 한 줄이 노출된다.
- 댓글 본문 안에 개인정보가 섞여 있을 수 있다. 작성자 정보는 저장하지 않지만 본문은 걸러 내지 않았다.

## 나무위키 Context 검색과 결과 근거

Context 검색은 API의 검색 후보 결합 단계에 연결되어 있다. Dense 사실 검색을
곡별 최고 점수로 집계한 뒤 Sparse 곡 프로필 순위와 내부 RRF로 결합하고,
기존 Text/Image/Audio 검색에는 하나의 보조 경로로 합류한다.

`POST /api/v1/search`의 `results[].context_evidence`에는 질의와 관련된 사실을
선택한 경우에만 `record_id`, `fact_text`, `source_url`, `section`, `category`가
포함된다. 관련성·출처 검사를 통과하지 않으면 근거는 비어 있다. Sparse 일치나
검색 점수 자체를 사실의 근거로 표시하지 않는다. 근거가 없다는 이유만으로
그 곡의 기존 검색 점수를 깎지 않는다. 이 검사는 원문 내용의 진위를 보증하지 않는다.

나무위키 원문, Context artifact, 임베딩, 로컬 Qdrant 데이터, 곡 목록,
평가 질의·라벨·분석 캐시·개인 실행 보고서는 공개 저장소에 올리지 않는다.
기존 `.env`의 Gemini 키와 공용 MongoDB URI도 공개하지 않는다. 공개 가능한 것은
검색 코드, 테스트 코드, 문서와 비밀 값이 없는 `.env.example`이다.

설정은 `load_context_settings()`가 검색 라우터 생성 시 환경변수에서 읽는다.
없으면 `CONTEXT_WEIGHT=0.5`, `CONTEXT_NAMED_MEDIA_MULTIPLIER=2.0`,
`CONTEXT_FACT_K=100`, `CONTEXT_SPARSE_K=100`, `SEARCH_DEFAULT_CANDIDATE_K=30`을
사용한다. `.env`를 바꾼 후에는 컨테이너를 재생성한다. 화면 `top_k=10`은
요청 스키마 기본값이며 이번 재검증에서 최적값을 새로 선택하지 않는다.

리랭킹 OFF인 동일 분석의 Context OFF/ON으로 Candidate@30, Hit@10, MRR@10,
회귀 손실, 실제 이미지·오디오 경로 실행과 표시 근거를 비교한다.
기존 dev 74문항/test 32문항/추가 60문항은 이미 관측한 질의다. 새 분석을
사용해도 새 블라인드 표본으로 간주하지 않는다. 수정 후 성능 주장은 새 실행의
`validation_report.json`과 `api_smoke_report.json`을 확인한 뒤 작성한다.
