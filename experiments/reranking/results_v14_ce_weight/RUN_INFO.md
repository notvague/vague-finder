# v0.14 — CE 최대 비중 제한 (비율 45 유지, 2026-09-23)

## 무엇을 재는가

Cross-Encoder 합성에는 계수가 둘이다.

```
작은 spread 구간(spread < spread_ref):
    유효 비중 = (rerank_weight / spread_ref) × spread      ← 비율이 결정
큰 spread 구간(spread ≥ spread_ref):
    유효 비중 = rerank_weight                              ← 최대 비중이 결정
```

현재 비율은 `0.9 / 0.02 = 45`다. **비율을 유지한 채 최대 비중만 낮추면**, 작은 spread
질의의 합성은 그대로 두고 큰 spread 질의의 CE 영향력만 제한할 수 있다.

앞선 v0.13 보고서에서 "가중치를 낮추면 test에서 얻은 이득을 반드시 잃는다"고 적었는데
**틀렸다.** test의 개선 질의 q201(spread 0.00124)·q306(0.00525)은 작은 spread 구간이라
비율을 유지하면 합성이 **비트 단위로 같다.**

## 조건

```
RERANKER_WEIGHT=<w> RERANKER_SPREAD_REF=<w/45> venv/bin/python -m src.retrieval.evaluate_search_accuracy \
    --input experiments/reranking/eval_queries_v05.csv --split <dev|test> \
    --analysis-cache experiments/reranking/analysis_cache_<split>.json \
    --output-dir experiments/reranking/results_v14_ce_weight/<조건>
```

| 조건 | `rerank_weight` | `spread_ref` | 구간이 바뀌는 질의 |
|---|---|---|---|
| `w090_*` (현행) | 0.90 | 0.020000 | — |
| `w045_*` | 0.45 | 0.010000 | **0건** (dev·test 모두) |
| `w040_*` | 0.40 | 0.008889 | dev 1건 |

`w045`는 구간 이동이 없어 **가중치 효과만 격리된다.**

### 비교 성립

| 확인 | 결과 |
|---|---|
| `candidate_digest` — 후보 전체의 id·순서·검색 점수 **+ CE가 읽는 곡 설명 문서** | dev 53/53, test 23/23 **동일** |
| `lyrics_source.content_sha256_16` | `af3e0c3cf03fed98` |
| `corpus.point_count` · `bm25.sha256_12` | 952 · `4710257067c8` |

digest에 CE 문서를 포함하도록 고쳤다 — id와 점수가 같아도 메타데이터가 바뀌면 CE는
다른 문서를 읽고 다른 점수를 낸다. 고친 뒤 기준선을 다시 재어 **요약 CSV가 완전히
같음**을 확인했다(달라진 열: digest와 벽시계 2개).

## 기록으로 계산한 경계와 맞는다

합성식에서 두 곡의 순서가 뒤집히는 가중치 경계를 기록값으로 풀면
(큰 spread 구간이라 신뢰도 1.0):

```
w* = (ret_B − ret_A) / [(ce_A − ce_B) + (ret_B − ret_A)]
```

| 질의 | 정답이 이기려면 | CE(상대/정답) | 검색(상대/정답) | 관측 |
|---|---|---|---|---|
| q219 | **w < 0.444** (현 1위 상대) | 1.0000 / 0.0380 | 0.2310 / 1.0000 | 0.45→2위, 0.40→1위 ✓ |
| q305 | **w < 0.780** (현 1위 상대) | 1.0000 / 0.7790 | 0.2150 / 1.0000 | 0.45→1위 ✓ |
| q215 | **w > 0.373** (검색 1위 「끝사랑」 상대) | 0.0001 / 1.0000 | 1.0000 / 0.4050 | 0.45·0.40에서 유지 ✓ |
| q212 | w > 0 (현 2위 상대) | 0.0000 / 1.0000 | 1.0000 / 1.0000 | 유지 ✓ |

**q215의 경계는 비교 대상에 따라 달라진다.** 처음에 최종 2위(「나만 안되는 연애」)
하나만 놓고 "w > −9.261, 어떤 가중치에서도 유지"라고 적었는데, 그것은 **그 두 곡
사이의 경계**일 뿐이다. 후보 전체와 비교하면 검색 1위였던 「끝사랑」 상대로
**w > 0.373**이 필요하다(CE는 0.0001로 낮지만 검색 정규화가 1.0이다).
측정한 0.45·0.40에서 유지된다는 결론은 맞지만, 여유가 크지 않다.

| q215 정답 상대 | 검색 순위 | CE | 검색 norm | 경계 |
|---|---|---|---|---|
| 끝사랑 | 1위 | 0.0001 | 1.0000 | **w > 0.373** |
| 솔직하게 말해서 나 | 2위 | 0.0001 | 0.9484 | w > 0.352 |
| 이제서야 | 3위 | 0.0000 | 0.7898 | w > 0.278 |

q212의 정답은 CE 1.0 / 검색 1.0으로 양쪽 모두 최상위라 어떤 w>0에서도 유지된다.

## 읽기

**w=0.40은 dev에서 phonetic 보호와 수치가 같고**(Hit@1 24/53, MRR 0.57812,
nDCG 0.63435, 3/49/1) — 둘 다 q219만 되살리기 때문이다 — **test에서는 q305까지
되살린다.** phonetic 보호는 test에서 아무것도 하지 않았다(발동 0건).

이 근거에서는 **비율 유지 가중치 인하가 phonetic 보호보다 넓게 작동한다.**

다만 단정하지 않는다.

1. 두 분할 합쳐 76건이다. 큰 spread 질의는 dev 5 + test 4로 더 적다.
   가중치 인하가 **순위를 바꾼** 것은 그 9건 안에서였다.
2. **영향 범위는 그 9건보다 넓다.** `w=0.40`에서는 `spread_ref`가 0.0089로 내려가
   **q313**(spread 0.009019)이 "상위 5개만 재정렬" → "후보 전체 재정렬"로 바뀌었다.
   반환 순서는 세 조건에서 같았지만 **처리 방식까지 같지는 않다.**
   `w=0.45`는 이 이동이 0건이라 가중치 효과만 격리된다.
3. `w=0.45`는 q219 경계(0.444)를 못 넘어 2위까지만 회복한다. 0.40이 경계 바로
   옆이라는 것은 **이 설정이 q219 한 건에 맞춰져 있을 위험**을 뜻한다.
4. m103은 어느 조건에서도 회복되지 않는다. 작은 spread 구간이라 비율이 결정하고,
   비율을 건드리면 작은 spread 질의 전체가 함께 움직인다.

## 다음

1. **비율 변경은 보류한다.** 기록에서 경계를 풀면 이미 상충한다 —
   m103의 정답이 현재 1위를 앞서려면 비율 **약 31.94 미만**이, q201의 개선을
   유지하려면 **약 41.05 초과**가 필요하다(후보·CE 점수와 정렬 방식이 유지된다는
   조건에서). 공통 비율 하나로 둘을 동시에 만족시킬 수 없다.
   탐색을 더 하기보다 가사 부스트 쪽을 먼저 본다.
2. **가사 부스트는 별건이다.** q211은 보호를 꺼도 오답이 1위였고, 그 CE는 정답을
   더 높게 평가했는데 유효 비중이 약 2.26%여서 큰 부스트 격차를 못 뒤집었다.
   **부스트와 낮은 CE 비중이 함께 만든 결과**이므로, 보호를 껐다는 실험만으로
   부스트 단독 원인이라고 확정할 수 없다. 부스트를 따로 바꾸는 비교가 필요하다.
   그때 ×8을 일괄 축소하기보다 **일치 구절 길이·일치 곡 수·partial/phonetic 여부**를
   먼저 기록하고, 짧거나 여러 곡에 겹치는 단서만 완화하는 쪽이 타당하다.
   짧다는 이유만으로 무조건 약화해서는 안 된다.
3. 한 번에 하나씩만 바꾼다. 기존 개선 질의(q208·q215·q310·q201·q212·q306)를
   매번 함께 확인한다.
