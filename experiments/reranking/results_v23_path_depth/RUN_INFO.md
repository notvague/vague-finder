# v0.23 — 정답이 어디서 빠지는지 기록하고, 경로 깊이만 넓혀 본다 · 2026-10-01

**결과: 경로 깊이는 지렛대가 아니다. 채택하지 않는다(깊이 30 유지, 팀 결정 2026-10-01).**

- 최종 후보 30 밖으로 빠진 정답 곡 25개 중 **23개는 어느 경로에서도 30위 안에 없었다.** 나머지 2개(c701·q118)는
  경로에는 잡혔지만 가산·감점 뒤 최종 절단에서 빠졌다. RRF 융합 절단에서 빠진 곡은 없다.
- 깊이를 40으로 넓히면 dev Hit@10이 36 → 38건으로 늘지만 Hit@3·Hit@5가 1건씩 줄고, test는 모든 지표가 같다.
  허용 정답을 넣은 확장 지표도 같은 방향이다.
- 넓힐수록 **멀리 있던 곡이 성별·장르 가산으로 후보에 밀려 들어온다.** 가산 1단위가 RRF 1위 기여보다 크기 때문이다.
  깊이 제한을 없애면 dev에서 4건을 얻고 5건을 잃는다.

## 조건 — 경로 깊이만 바꿨다

v22(`results_v22_corpus3010`)와 같은 코드·코퍼스(3,010곡)·분석 캐시(`analysis_cache_v06_{dev,test}.json`)·
CE 설정(가중치 0.45, 앞 20개 채점)이다. 바꾼 것은 **세 기본 경로(text·image·audio)의 깊이와 RRF 절단 수** 하나다.

| | 지금 | 이 실험 |
|---|---|---|
| 세 기본 경로 깊이 · RRF 절단 | 30 | `path_k` (40 등) |
| 최종 후보 수 | 30 | **30 그대로** |
| CE 채점 | 앞 20개 | **20 그대로** |
| 보조 신호(metadata·performance)가 보는 목록 | 원래 깊이 | **원래 깊이 그대로** |

- `candidate_k`를 올리면 경로 깊이와 최종 후보 수가 함께 바뀌고 리랭커의 검색 점수 정규화 범위까지 달라진다
  (v21에서 test q201이 그 때문에 1위 → 2위로 내려간 적이 있다). 그래서 깊이만 따로 넘기는 인자를 새로 뒀다 —
  `SearchRouter.search(path_k=)` · `evaluate_search_accuracy --path-k`. **생략하면 기존 동작과 같다**(`tests/test_path_depth.py`).
- 보조 신호는 원래 깊이 목록만 본다. 깊은 곡이 metadata·performance 상위 15에 끼면 기존 후보의 점수까지 바뀌어
  "깊이만 넓힌" 비교가 되지 않는다.
- 텍스트 하이브리드는 컬렉션 전체를 합산한 뒤 자르므로(`qdrant_backend.py`) 깊이를 늘려도 상위 순서는 같고 뒤에
  곡이 붙기만 한다. 이미지·오디오는 정확 검색이다. 즉 기존 후보의 점수는 그대로이고 **새 곡이 들어올 수 있을 뿐이다**.

## 1. 정답이 어디서 빠지나

```bash
venv/bin/python -m src.retrieval.trace_candidate_drop --split dev \
    --analysis-cache experiments/reranking/analysis_cache_v06_dev.json \
    --output experiments/reranking/results_v23_path_depth/candidate_drop_dev.csv
```

같은 분석으로 검색을 두 번 한다(리랭킹 없음). 한 번은 지금 깊이로 **어느 단계에서 빠졌는지**, 한 번은 깊이 제한 없이
(`path_k=3010`, 전수) **각 경로에서 몇 위인지, 그리고 깊이 제한이 없을 때 보정 뒤 몇 위가 되는지**를 본다.
지금 깊이의 후보 순위는 v22 detail의 `candidate_rank@30`과 82건 모두 같다.

| 단계 | 뜻 |
|---|---|
| 경로 밖 | 어떤 경로(기본·보조)의 목록에도 없었다 |
| 융합 절단 | 기본 경로 목록에는 있었지만 RRF 절단(30)에서 빠졌다 |
| 보정 뒤 절단 | 융합 목록에는 있었지만 보조 경로·가산·감점 뒤 최종 30 밖이었다 |

정답이 후보 30 밖인 질의 dev 11 · test 5건, 정답 곡 25개(질의 하나에 정답이 여럿인 경우가 있다):

| 질의 | 단계 | 텍스트 순위 | 이미지 | 오디오 | 깊이 무제한일 때 보정 뒤 |
|---|---|---|---|---|---|
| dev q110 | 경로 밖 | **33** | – | 1458 | 21 |
| dev q208 | 경로 밖 | **38** | – | – | 7 |
| dev q210 | 경로 밖 | **33** | 398 | – | 16 |
| dev c603 | 경로 밖 | **32** | – | – | 32 |
| dev q112 | 경로 밖 | 238 | – | 1216 | 3 |
| dev q115 | 경로 밖 | 222 | – | 152 | 49 |
| dev q203 | 경로 밖 | 132 | – | 576 | 135 |
| dev q117 (정답 5곡, 열마다 최솟값) | 경로 밖 | 162 | 274 | – | 274 |
| dev m302 (정답 5곡, 열마다 최솟값) | 경로 밖 | 497 | 82 | – | 111 |
| dev m403 (정답 2곡, 열마다 최솟값) | 경로 밖 | 316 | 1903 | 319 | 350 |

읽는 법:

- **경계 바로 밖은 4건뿐이다** — q110·q208·q210·c603의 정답이 텍스트 31~38위다. 경로 깊이로 구할 수 있는 것은 이들이다.
- 나머지는 수백~수천 위다. 깊이가 아니라 **검색 신호**의 문제다. 특히 표지 질의(q117·m302·m403·m401)는 이미지
  경로에서도 82~2590위라 SigLIP이 표지를 찾지 못하고 있다.
- 보정 뒤 절단 2건(c701·q118)은 둘 다 **misinformation 질의**다. 사용자가 일부러 틀리게 말한 성별에 걸려 감점
  (−1단위)을 받고 30 밖으로 밀렸다.

## 2. 넓히면 무엇이 들어오나 — 가산이 깊은 곡을 끌어올린다

```bash
venv/bin/python -m src.retrieval.trace_candidate_drop --split dev \
    --analysis-cache experiments/reranking/analysis_cache_v06_dev.json \
    --sweep 35,40,45,50,60,80,100 \
    --output experiments/reranking/results_v23_path_depth/candidate_depth_sweep_dev.csv
```

정답이 최종 후보 30 안에 든 질의 수 (리랭킹 없음):

| 경로 깊이 | dev 엄격 | dev 확장 | test 엄격 | test 확장 | 지금 대비 (엄격) |
|---|---|---|---|---|---|
| 30 (지금) | 46 | 51 | 20 | 22 | |
| 35 | 46 | 51 | 20 | 22 | dev +q110·q210 −q316·c705 |
| 40 | 47 | 52 | 20 | 22 | dev +q110·q208·q210 −q316·c705 |
| 45~60 | 47 | 52 | 19 | 21 | 위 + test −q102 |
| 80~100 | 45 | 51 | 19 | 21 | dev −c601·c707 추가 |
| 무제한 | 45 | – | 17 | – | dev +q110·q112·q208·q210 −q316·c601·c607·c705·c707, test −q102·c606·c703 |

(dev 57 · test 25. 무제한은 1절 추적의 전수 실행이다.)

**왜 얻는 만큼 잃나.** 가산 1단위(`boost_unit = 1/61 ≈ 0.0164`)가 RRF 기여 차이보다 크다. 텍스트 가중치 0.7일 때 RRF
기여는 1위 0.0115, 30위 0.0078, 40위 0.0070이다. 성별이나 장르가 한 번 맞으면 40위 곡이 1위 곡을 넘는다. 깊이를
넓히면 **"검색이 비슷하다고 본 곡"이 아니라 "메타데이터가 맞는 곡"이 후보로 들어온다.** 깊이 35에서 먼저 빠진
q316·c705의 정답은 텍스트 경로 2위·7위였다. 둘 다 misinformation 질의라 말한 성별과 달라 감점(−1단위)을 받고
이미 후보 30·27위에 걸려 있었다. 지금 깊이에서도 같은 일이 보인다 — c707의 정답은 텍스트 1위인데 후보 18위다.

## 3. 깊이 40 전체 측정 (CE 포함)

```bash
venv/bin/python -m src.retrieval.evaluate_search_accuracy --split dev \
    --analysis-cache experiments/reranking/analysis_cache_v06_dev.json \
    --output-dir experiments/reranking/results_v23_path_depth/pathk40 --path-k 40
venv/bin/python -m src.eval.relaxed_metrics --result-dir experiments/reranking/results_v23_path_depth/pathk40
```

리랭킹 결과(rerank) 기준, 괄호는 건수:

|---|---|---|---|
| Hit@1 | .386 (22) → .386 (22) | .491 (28) → .491 (28) | 엄격·확장 모두 v22와 같음 |
| Hit@3 | .491 (28) → .474 (27) | .614 (35) → .596 (34) | |
| Hit@5 | .561 (32) → .544 (31) | .719 (41) → .702 (40) | |

| MRR@10 | .4488 → .4505 | .5710 → .5724 | |
| Candidate Recall@30 | .788 → .806 | | .754 → .754 |

질의별 (dev): 좋아짐 q110(후보 밖 → 10위) · q208(밖 → 7위) · q101(9 → 7위), 나빠짐 q218(3 → 4위) · q312(5 → 6위) ·
q106(4 → 5위) · c706(9 → 10위). test는 top-10 안 정답 순위가 모두 같다.

**확장 지표는 공정하게 셌다.** 깊이 40에서 새로 top-10에 든 곡 중 지난 라벨 검토에서 본 적 없는 곡이 있었다
(모호 질의 34쌍). 멜론 메타데이터·가사 원문·표지로 26쌍을 부적합 또는 허용 아님으로 판정했고, 남은 곡은 모두 그 질의의
**첫 정답(원래 타깃 + 허용 정답)보다 아래**라 판정 결과와 관계없이 리랭킹 확장 지표가 바뀌지 않는다. 남은 곡도 팀이
들어 보고 판정했다(2026-10-01) — v24 후보까지 합친 42쌍 중 허용 정답 2곡(m402·q116), 나머지는 부적합·허용 아님이다.
두 곡을 넣은 v08 라벨(`eval_queries_v08.csv`)로 다시 세어도 v21·v22·이 측정·v24의 확장 지표 요약은 v07과 바이트 단위로 같다. 검토 기록은
`data/label_review_v22/추가검토_v23_깊이40.xlsx`와 `_scripts/extra_v23.py`(비공개)에 있다.

## 결정과 다음

- **깊이 30 유지.** 얻는 것은 7·10위 2건이고 잃는 것은 상위권 순위 3건이다. test q102의 정답은 후보 21 → 28위로
  밀려 45부터는 후보에서 빠진다. `path_k`는 기본값에서 꺼 둔 채 다음 실험을 위해 남긴다.
- 후보에서 빠지는 원인은 깊이보다 이쪽이다 — 다음 실험 후보로 남긴다.
  - 가산 크기와 RRF 차이의 균형: 가산이 검색 순위를 압도해 메타데이터가 맞는 먼 곡이 후보를 차지한다
  - 표지 질의의 이미지 경로: 정답이 수백~수천 위다
  - misinformation 질의의 성별 감점: c701·q118이 감점으로 후보에서 빠진다
