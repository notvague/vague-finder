# results_v40 — 모달리티 규칙의 한 글자 낱말 오탐(록·별 등) 수정과 그 효과 (2026-10-11)

v10 첫 측정(`results_v38_v10_dev_first`)에서 질의 분석이 규칙 폴백으로 떨어진 4건의 원인을 고치고, **고치면 검색 결과가 실제로 나아지는지** 쟀다.

- 워크트리 `../vague-finder-modality-fix` · 브랜치 `fix/modality-token-boundary` (main `525d918`, 색인은 `artifacts/` 복사본)
- 코드 변경: `src/retrieval/modality_queries.py` 한 파일(+27 −5) · 테스트 `tests/test_modality_token_boundary.py`(24건). 전체 테스트 1,506 통과(기존 macOS `/tmp` 1건 제외)
- 측정 조건은 v38·v39와 같다(5,143곡 · listwise 기본 · AI Studio · `SEARCH_REFERENCE_YEAR=2026`). 분석 프롬프트는 건드리지 않았다(`08f0b3bc4c37`)

## 1. 원인

`apply_modality_query_safeguards`는 규칙이 "소리(표지) 단서가 있다"고 판정했는데 모델이 그 프롬프트를 내지 않으면 예외를 낸다. 3회 반복되면 **분석 전체**가 규칙 폴백이 된다.
그 규칙이 한 글자 낱말을 다른 낱말의 조각에서 읽고 있었다.

| 글자 | 읽힌 곳 | 규칙이 본 것 | 걸린 질의 |
|---|---|---|---|
| 록 | 초**록** · 수**록**된 · 알**록**달**록** · 좋아할수**록** | 록 장르 → 소리 단서 | t071 · t086 · t099 |
| 락 | 손가**락** | 록 장르 → 소리 단서 | (dev에는 없음) |
| 별 | 이**별** · 특**별** | 별 그림 → "앨범" + 표지 묘사 | t009 |
| 비 | 준**비** · **비**트 · 알앤**비** | 비 그림 → "앨범" + 표지 묘사 | n002 (v09) |
| 해 · 달 | 기억**해** · 유명**해** · **달**리는 · **달달**한 | 해·달 그림 | (dev에는 없음, 같은 구조) |

평가 질의 281건에서 이 글자들이 실제로 쓰인 곳(§4 `rules_before.csv`): 록 41회 중 19회가 조각, 달 14회 전부, 해 37회 거의 전부, 비 30회 중 25회, 별 11회 중 8회. 색·빛·꽃은 전부 제 뜻으로 쓰여 그대로 뒀다.

## 2. 고친 것

**낱말의 첫 글자일 때만 읽는다.** 예문별 예외를 붙이지 않고 한 가지 규칙으로 통일했다.

- `_ROCK` — 록·락 앞에 한글이 붙어 있으면 받지 않는다. 붙여 쓰는 장르 이름(하드·모던·펑크·포크·팝·인디·얼터너티브·브릿 등 + 록)만 따로 연다. `_STRONG_AUDIO_RE` · `_AUDIO_GENRE_RE` · 폴백 프롬프트 표(`_AUDIO_FEATURES`의 "a rock style") 세 곳에 같은 것을 쓴다
- `_one_syllable_noun` — 별·달·해·비는 낱말 첫 글자이고 뒤가 조사·낱말 끝일 때만("별이", "별들이", "별무늬", "비가") 그림 속 사물로 본다. `_VISUAL_DETAIL_RE`와 암시적 표지 묘사의 `subject` 축에 쓴다(기존 `(?<!이)별`은 "특별·별로"를 못 막았다)

| | 판정 |
|---|---|
| 초록 풀밭 · 수록된 · 알록달록 · 좋아할수록 · 손가락 | 소리 단서 아님 |
| 록밴드 · 펑크록처럼 · 하드록 · 록발라드 · 팝록 · 신나는 락 · 모던 록 | 소리 단서 (그대로) |
| 이별 · 특별한 · 별로 · 준비 · 비트 · 기억해 · 달리는 · 달달한 | 표지 묘사 아님 |
| 별이 그려진 · 별들이 · 별무늬 · 비가 오는 · 해가 뜨는 · 달이 뜬 | 표지 묘사 (그대로) |

## 3. 효과

### 3-1. 분석

| | 전 | 후 |
|---|---|---|
| 폴백으로 떨어지는 질의 (v10 dev 60 + v09 dev 59 + v06 dev 57) | **6** (t009·t071·t086·t099·n002·n025) | **1** (n025) |
| 그 5건의 분석 시간 (Gemini 호출 포함, `time_analysis.py`) | 평균 **7.8초** (3회 호출 + 대기) | 평균 **2.1초** (1회) |
| 표지만 말한 t086·t099의 소리 프롬프트 | "An audio track with a rock style." · 소리 가중 0.4 | 없음 · 텍스트 1.0 |

- n025는 다른 이유다 — 모델이 소리 프롬프트에 "pop **star**"를 쓰고 누출 검사(`_VISUAL_LEAK_IN_AUDIO_RE`의 `stars?`)가 이를 표지 낱말로 읽는다. 폴백인 채로도 정답 1위라 이번에는 고치지 않았다
- 봉인 test에서 규칙 판정이 바뀌는 질의: v10 test **2건**(t090·t094, "초록" → 소리 단서 해제). 고치지 않으면 이 둘도 같은 폴백을 탈 가능성이 높다. v06·v09 test는 판정이 바뀌는 질의 없음

### 3-2. 기존 질의에 부작용이 없는가

- 규칙 판정(표지·소리 단서 유무)이 바뀌는 질의: 281건 중 **7건** — 위 폴백 5건 + v10 test 2건. **참 → 거짓 방향만** 있다
- 캐시에 저장된 분석 233건(폴백 제외, v06·v09 dev/test + v10 dev)에 고친 규칙을 다시 적용하면 **232건이 그대로**다. 남은 1건(n057)은 고치기 전 코드로도 똑같이 달라지는 항목이다(`reapply_safeguards.py`)
- 그래서 v06·v09 기준선 숫자(`results_v39_corpus5143_baseline`)는 n002 한 건 말고는 영향이 없다

### 3-3. 검색 결과 — **정답 회수는 달라지지 않는다**

분석이 바뀐 5건만 다시 쟀다(2회, 두 번 같음). 나머지는 분석이 같다.

| ID | 정답 | 전 (폴백) | 후 (모델 분석) |
|---|---|---|---|
| t009 | 뜨거운 안녕 - 토이 | 후보 밖 (T648) · 10위 밖 | 후보 밖 (T1127 · A753) · 10위 밖 |
| t071 | Fly - 에픽하이 | 후보 밖 (T89) · 10위 밖 | 후보 밖 (T199) · 10위 밖 |
| t086 | 숲 - 최유리 | 후보 2 · **7위** | 후보 2 · **7위** |
| t099 | 꽃 - 지수 | 후보 밖 (T276) · 10위 밖 | 후보 밖 (T93) · 10위 밖 |
| n002 | 사랑할수록 - 부활 | 후보 밖 (T160, 깊이 1) · 10위 밖 | 후보 밖 (T552, 깊이 3) · 10위 밖 |

- v10 dev 후보 30 안 32 → 32 · Hit@10 32 → 32 · Hit@1 16 → 16. v09 dev 후보 40 → 40 · Hit@10 38 → 38
- t009·t071·n002는 가수 사연·게임 수록 같은 **외부 사실** 질의라 분석이 제대로 돼도 텍스트 경로가 못 찾는다(RUN_INFO v38 §3의 C·E 갈래). 텍스트 순위는 오히려 내려간 것도 있다
- t086·t099는 폴백이 풀려도 **표지 경로가 여전히 꺼져 있다** — 아래 3-4

### 3-4. 가정 실험: 표지 경로가 열리면 (`probe_image_path.py`, 규칙은 안 바꿈)

t086·t099는 "…한 이미지"로 끝나는 표지 묘사인데 "표지·커버·앨범"이라는 말이 없어 `has_explicit_visual_clue`가 거짓이고, 모델이 낸 표지 프롬프트를 규칙이 지운다.
이 두 질의만 표지 단서로 인정해 다시 분석하면:

| ID | 표지 경로 순위 | 후보 | 최종 |
|---|---|---|---|
| t086 | 5 (텍스트 2) | 2 → **1** | 7위 → **1위** |
| t099 | **1** (텍스트 93) | 밖 → **2** | 10위 밖 → **2위** |

- 두 건 모두 살아난다 — v10 dev로는 Hit@10 32 → 33 · Hit@1 16 → 17에 해당한다. 단 **토큰 수정이 먼저 있어야 한다**(없으면 "초록" 때문에 어차피 폴백)
- "이미지"가 든 질의는 281건 중 9건. 표지 단서로 안 읽히는 것은 5건 — dev의 t086·t099, q215("생각나는 이미지가 검은색?" — 심상이라 안 읽는 게 맞다), test 3건(n005·t089·t090)
- 이 실험은 **규칙을 만든 것이 아니다.** "이미지"는 "청순한 이미지의 가수"처럼 인상을 뜻하기도 해서, 규칙으로 열면 새 오탐이 생길 수 있다. 여는 규칙을 정하고 전 질의에서 판정이 바뀌는 것을 본 뒤에 따로 잰다

## 4. 결론

- 토큰 경계 수정은 **맞는 수정이고 부작용이 없지만, 정답 회수 숫자는 올리지 않는다.** 얻는 것은 폴백 6 → 1, 해당 질의 분석 시간 7.8 → 2.1초, 엉뚱한 "rock style" 소리 프롬프트 제거, 봉인 test 2건의 폴백 예방
- 숫자가 움직이는 것은 그 다음 단계 — "…이미지"로 끝나는 표지 묘사를 표지 단서로 읽는 규칙(가정 실험에서 2건 회복)
- 구조 문제는 남는다: 규칙과 모델이 한 모달리티에서 어긋나면 분석 전체를 버린다. 이번에 그 사례(프롬프트 누락형)는 토큰 수정으로 다 풀려 **지금 데이터로는 효과를 잴 사례가 없다** — 다음 오탐을 대비한 안전장치로만 의미가 있어 구현하지 않았다
