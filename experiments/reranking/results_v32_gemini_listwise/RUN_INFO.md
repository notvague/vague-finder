## 읽는 법

> **보정(2026-10-09, PR #16~#22 리뷰)**: 여기서 "grounding 끔"(`GEMINI_RERANK_USE_SEARCH=0`)은 **일반 listwise 패스의 Google Search grounding만** 끈 것이다.
> 희소 사실 교차검증(`_verify_rare_facts`)은 이 설정에서도 드라마·영화·OST·예능 등 희소 단서 정규식에 걸리는 질의(dev 57 중 11건: q105·q203·q207·q209·q219·m103·m104·c607·c701·c705·c707)에
> Google Search 도구로 15곡 단위 검증 호출(2회)을 돌렸다. 그래서 이 기록만으로는 "웹 검색 없이 LLM 자체 지식으로 돌아온다"고 말할 수 없다.
> 웹 검색을 완전히 뺀 대조군은 `results_v35_rare_verify_off`(검증까지 끔)다 — 1패스·검증 켬 대비 v06 dev Hit@10 42 → 43(기준 `nosearch_pass1`), v09 dev 42 → 41(기준 `results_v33_v09_dev/lw_pass1`), 합산 84 → 84로 같고(본문 표의 44는 2패스), 검증의 구조 규칙은
> 3,010곡 기록 전부에서 정답을 올린 적이 없다. 즉 아래 해석("핵심은 웹 검색이 아니라 후보 30개를 통째로 보는 것")은 v35로 뒷받침된다. 현재 기본값은 검증도 끈 설정이다.

- **효과의 핵심은 웹 검색이 아니라 "후보 30개를 통째로 보고 순서를 정하는 것"이다.** grounding을 꺼도 엄격 Hit@10 44로 같다. c602(쇼미더머니)·c607(응답하라 리메이크)
  같은 외부 맥락 질의는 LLM 자체 지식으로 돌아온다. grounding은 확장 지표를 1건 더 보태는 대신 5초를 더 쓴다
- **왜 CE는 못 하고 LLM은 하나.** CE(bge-reranker-v2-m3-ko)는 (질의, 곡 문서) 쌍마다 점수를 내는데 이 질의 유형에서 점수 폭이 0.003 수준이라 후보를
  못 가른다(v29). LLM은 후보끼리 비교하고 배경지식을 쓴다. c602는 텍스트 경로 23위·후보 24위였는데 1위로 올렸다
- **변동.** 같은 설정을 두 번 돌리면 순위가 다른 질의가 13~16건이고 Hit@10은 ±1, Hit@1은 ±3이다(temperature 0인데도 Search 결과와 모델 응답이 흔들린다).
  이득이 그보다 크지만, **서비스에서 같은 질의가 다른 순서를 내놓는다**는 뜻이기도 하다. 설명 기능(§4 원칙)과 데모에서 감안해야 한다
- **1패스는 지연을 반으로 줄이고 이득의 2/3를 남긴다** (엄격 +5, 5.4초). 요청 전체로는 CE 1.8초를 빼고 더해 중앙값 약 8초, p95 약 20초다
- **주의 — 9월 리뷰의 4번 지적이 그대로 남아 있다.** 리랭커의 희소 단서 정규식(애니·드라마·OST / 휘파람·인트로 / 알파벳·한자 제목)은 이 평가 질의들을 보고 만든
  것이라 dev 숫자는 **낙관적일 수 있다.** 봉인 test(v09) 없이는 채택 근거가 안 된다
- 미검토 쌍(첫 정답 위의 새 후보)은 grounding·nosearch 모두 36쌍이다. 판정 전 확장 지표는 낮은 쪽으로 치우쳐 있다
