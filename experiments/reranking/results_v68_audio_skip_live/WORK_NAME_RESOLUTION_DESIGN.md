# 간접 지칭 작품명 해석 — 설계 초안(구현 없음)

작성 2026-10-17(v68). **이번 범위에서 구현·프롬프트 변경·캐시 재생성·모델 실험을 하지 않았다.** 기존 실패 질의에 정답 작품명을 붙이는 규칙도 만들지 않는다. A/B 결과 뒤 주 개발 후보로 검토하기 위한 설계다.

## 1. 문제와 지금까지의 근거

- 질의가 드라마·예능·경연 프로그램·영화를 **이름 없이 줄거리·인물·상황으로만** 말하고("의사 다섯 명이 밴드 하는 드라마", "힙합 경연 프로그램 우승자"), 정답 곡 자료에는 고유명이 있다(album_summary — BM25 sparse 색인에 들어감 · Context 사실 639곡).
- v67 진단: 후보 밖 54건 중 14건, 후보 내 실패 5건 중 4건에 이 꼬리표가 붙었다. 이 14건은 주 원인 표(A·R·P·B·L)를 **가로지르는 겹치는 묶음**이다 — 주 원인으로는 A 5 · R 4 · P 3 · B 1 · L 1이며, 주 원인 합계에 더하는 수가 아니다.
- 수동 주입 진단: 사람이 정한 작품명을 분석 태그에 하나 더했을 때 후보 밖 9질의 중 6질의가 후보 30에 들었다(리랭킹 전). **보인 것은 검색 단계의 가능성까지다** — "고유명이 질의 쪽에 들어오면 현재 색인이 정답을 30 안으로 가져올 수 있다". 보이지 않은 것: ① 자동 해석기가 그 이름을 맞힐 확률 ② 틀린 이름의 피해 ③ 리랭킹 뒤 결과 ④ 다른 질의에 생기는 손실. 대조 질의 c607(자료에 이름 없음)도 후보에 들어 우연 일치가 섞였을 수 있다. 그래서 +6은 예상 효과·최대 이득으로 쓰지 않는다.

## 2. 단계 설계

```
질의 → [1] 간접 지칭 판정 → [2] 작품명 후보 생성(0~k개, 확신도) → [3] 해석 보류 판정 → [4] 보조 검색 단서로만 사용 → 융합 → 리랭킹
```

1. **간접 지칭 판정(규칙, 모델 없음)**: 분석의 `context_clues`(관계가 삽입곡·OST·경연·리메이크 등)가 있는데 `target`이 비었거나 고유명이 아닌 서술 조각("대사로 그", "나중", "비행사 얘기 다룬")인 경우. 질의 원문에 작품을 가리키는 일반명(드라마·예능·오디션·경연·영화·애니)과 줄거리 서술이 함께 있는 경우. 판정 규칙은 query_id·정답 곡을 쓰지 않는 일반 규칙으로, 결과를 보기 전에 문서화한다.
2. **작품명 후보 생성**: 별도 모델 호출(질의 원문만 입력, 곡 정보·색인 내용 없음) → 작품명 0~k개(k ≤ 3)와 각 확신도, "모르겠다"를 허용. 기존 분석 프롬프트에 넣으면 176 분석이 모두 바뀌므로(CLAUDE.md — 프롬프트 변경 = 캐시·기준선 재생성) **별도 단계**를 우선 검토한다. 판정 [1]이 참일 때만 부른다(호출 수 제한).
3. **해석 보류**: 후보가 없거나 최고 확신도가 기준 미만이면 아무것도 하지 않는다(현행과 같은 검색). 후보가 여럿이고 확신도가 비슷하면(모호한 줄거리) 상위 k개를 모두 보조 단서로 쓰되 개수를 늘리지 않는다.
4. **사용 방식 — 강한 필터가 아니라 보조 검색 단서**:
   - **하지 않는다(강한 필터)**: 작품명으로 후보를 거르거나, 작품명이 안 맞는 곡을 감점·제외. 틀린 이름 하나가 정답을 후보에서 지운다. 사용자가 작품을 잘못 기억한 경우(v67 L 5건처럼 기억 오류가 실제로 흔하다)도 같은 피해.
   - **한다(보조 단서)**: 작품명으로 BM25 보조 조회(album_summary) · Context 조회(작품명 일치 경로)를 **추가 RRF 목록(작은 가중)**으로 넣는다. 기존 경로·후보는 그대로 두고 후보를 더할 기회만 준다. 최종 후보 30의 절단 규칙은 같다.
   - 리랭커에 작품명을 "사실"로 넘기지 않는다(환각 설명 방지 원칙 — 근거 없는 작품명이 설명에 나오지 않게). 리랭커 입력 변경은 별도 실험.

## 3. 위험과 대응

| 위험 | 예 | 대응 |
|---|---|---|
| 복수 후보 | 줄거리가 여러 작품에 맞음 | 상위 k ≤ 3을 모두 보조 단서로, 확신도 비례 가중. 후보 수가 늘수록 잡음 — k별 손실을 오프라인으로 잰다 |
| 모호한 줄거리 | "재벌 나오는 드라마" | 판정 [1]·보류 [3]에서 걸러 현행 유지 |
| 틀린 기억 | 사용자가 다른 작품을 말함 | 보조 단서라 기존 후보를 지우지 않음. 손실은 "보조 목록이 후보 끝자리를 바꾼 질의"로 측정 |
| 잘못 해석한 작품명 | 해석기가 엉뚱한 작품을 답함 | 같은 이름을 가진 다른 곡이 후보 끝자리를 밀 수 있다 — 작은 가중·절단 전 위치 제한, 가짜 해석기(일부러 틀린 이름)로 손실 상한 측정 |
| 곡 제목과 같은 작품명 | 영화명 = 곡 제목(n096) | 제목 경로와 겹쳐 효과를 부풀린다 — 진단 표에서 따로 센다 |
| 자료에 이름 없음 | Context 사실 없음·album_summary에 이름 없음(c607) | 해석해도 못 찾는다. 이름 일치가 아닌 우연 일치(c607)를 효과로 세지 않게 일치 필드를 기록 |
| 호출 비용·지연 | 질의당 1회 추가 | 판정 [1]이 참일 때만, 제한 시간 넘으면 보류(현행 검색) |
