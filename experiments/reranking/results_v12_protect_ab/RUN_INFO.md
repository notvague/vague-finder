# v0.12 — 보호 규칙 A/B (2026-09-22)

v0.11에서 리랭커가 순위를 내린 두 질의(q219·m103)를 각각 겨냥한 규칙을 **따로** 켜고
비교했다. 두 규칙을 같이 켠 조건은 재지 않았다 — 어느 쪽이 무엇을 했는지 먼저 봐야 한다.

## 조건

같은 분석 캐시 · 같은 Qdrant 인덱스 · 같은 Mongo 가사에서 스위치만 바꿨다.

| 조건 | 스위치 | 내용 |
|---|---|---|
| `current/` | (없음) | v0.11과 동일. exact 가사 일치만 보호 |
| `phonetic_protect/` | `LYRIC_PROTECT_PHONETIC_TOP1=1` | **검색 1위인** phonetic 표면 일치도 보호 |
| `skip_small_spread/` | `RERANKER_MIN_SPREAD=0.002` | CE spread가 0.002 미만이면 재정렬을 아예 생략 |
| `no_lyric_protect/` | `LYRIC_PROTECT_MIN_CONFIDENCE=1.01` | **진단용** — 가사 보호를 전부 끈다 |

```
venv/bin/python -m src.retrieval.evaluate_search_accuracy \
    --input experiments/reranking/eval_queries_v05.csv --split dev \
    --analysis-cache experiments/reranking/analysis_cache_dev.json \
    --output-dir experiments/reranking/results_v12_protect_ab/<조건>
```

### 비교가 성립하는가 — 먼저 확인했다

| 확인 | 결과 |
|---|---|
| **리랭커 입력 전체** `candidate_digest` (후보 30개의 id·순서·검색 점수 해시) | 53건 전부 **동일** |
| `corpus.point_count` | 952 (동일) |
| `bm25.sha256_12` | `4710257067c8` (동일) |
| **`lyrics_source.content_sha256_16`** (곡 ID+가사 내용 해시) | `af3e0c3cf03fed98` (동일) |
| `analysis.meta.analyzer.prompt_sha` | `08f0b3bc4c37` (동일) |

리랭커에 들어간 입력이 같으므로 차이는 전부 리랭킹 단계에서 나온 것이다.

처음에는 `baseline_top_ids`(상위 10개)와 `candidate_rank@30`(정답 위치)만 비교했는데,
**그것으로는 나머지 후보와 검색 점수가 같다는 보장이 없다.** 가사 지문도 길이 합만
남겼는데 "너를 사랑해"와 "너를 미워해"는 길이가 같다. 둘 다 내용 해시로 바꿨다.

실험 스위치는 `runinfo.json`의 `ranking_switches`에 **실제 적용된 값**으로 남는다
(환경변수를 다시 읽지 않고 코드에서 읽는다). 폴더명과 이 문서에만 의존하지 않는다.

| 조건 | `ranking_switches` |
|---|---|
| current | `phonetic_top1=false, min_confidence=0.8, min_spread=0.0` |
| phonetic_protect | `phonetic_top1=true, min_confidence=0.8, min_spread=0.0` |
| skip_small_spread | `phonetic_top1=false, min_confidence=0.8, min_spread=0.002` |

## 읽기

**phonetic 보호가 낫다.** q219를 되찾으면서 기존 개선 3건을 전부 지켰고, 새로 잃은
질의가 없다(악화 2건 → 1건). MRR +0.0126, nDCG +0.0094.

발동 범위도 좁다 — 53건 중 **새로 보호된 곡은 q219의 정답 1곡뿐**이다
(보호 적용 곡 2건 → 3건). 검색 1위로 제한한 설계가 의도대로 동작했다.

**spread 생략은 q219에 효과가 없다.** q219의 CE spread는 0.573(신뢰도 1.0)이라
저신뢰 구간에 들어가지 않는다. 두 문제는 원인이 다르다.

**그리고 q310을 잃는다.** 임계값으로 둘을 분리할 수 없다 —

```
q310 spread 0.000125   (개선 3→2위)
m103 spread 0.000811   (악화 1→2위)
```

m103을 잡는 임계값은 **반드시** q310보다 커야 하므로 q310도 함께 꺼진다. 0.002에서는
53건 중 **41건이 재정렬을 건너뛴다**(77%). 그렇게 많이 끄고 얻은 것이 순위가 실제로
바뀐 6건뿐이고, 그중 지표가 움직인 것은 m103(+1)과 q310(−1)이다.

| 재정렬을 건너뛰어 순위가 바뀐 6건 | 현행 → 생략 | 기준 |
|---|---|---|
| q101 | 밖 → 밖 | 밖 |
| q209 | 1위 → 1위 | 1위 |
| q210 | 6위 → 6위 | 6위 |
| q308 | 1위 → 1위 | 1위 |
| q310 | 2위 → **3위** | 3위 |
| m103 | 2위 → **1위** | 1위 |

## 보호 규칙 자체의 비용 — 끄고 재 봤다

"보호가 리랭커의 올바른 교정을 막는가"를 확인하려고 보호를 전부 끈 조건을 더 쟀다.

**지표가 현행과 완전히 같다.** 결과가 달라진 질의는 53건 중 **q213 하나**이고,
그마저 3·4위가 자리를 바꾼 것뿐이라 정답은 1위 그대로다.

### q211 — 내 가설이 틀렸다

보호가 오답을 1위에 고정한 사례로 q211을 지목했었다. 확인해 보니 **아니다.**

```
질의: "위험하다는 가사가 반복적으로 나오는 노래 … 여러 명의 여자가 같이 부르는"
1위 우원재 - 시차 (We Are)   ← 정답 아님. "위험하다"가 가사에 있어 ×8.0 부스트
2위 마마무 - Decalcomanie     ← 정답. 텍스트 1위, 성별·편성 전부 일치
```

보호를 꺼도 상위 순서가 **그대로다**(`30613202|30079086|420520`). 즉 이 오답을 1위로
만든 것은 보호 규칙이 아니라 **가사 표면 부스트 ×8.0**이다. 단서가 "위험하다" 네 글자
partial이어서 다른 곡에 걸렸고, 그 부스트(+0.1180)가 텍스트 경로 기여(+0.0164)의 7배다.

→ **여러 곡에 겹치는 구절의 위험은 보호 규칙이 아니라 부스트 배수에 있다.**
   보호를 좁히거나 넓혀도 이 사례는 달라지지 않는다.

### 보호가 실제로 의미를 갖는 지점

| 조건 | q219 정답 순위 |
|---|---|
| 현행(보호 없음) | 3위 |
| 보호 전체 끔 | 3위 |
| **phonetic 보호** | **1위** |

q219의 CE spread는 0.573(신뢰도 1.0)이다. **리랭커가 강하게 움직이려 할 때만** 보호가
결과를 바꾼다. 그 외에는 부스트가 이미 순서를 정해 놓아 보호가 할 일이 없다.

### 그래도 남는 위험

측정으로 드러나지 않은 비용이 있다. **보호는 곡이 맞는지 보지 않는다** — 짧은 음차
구절이 엉뚱한 곡에 걸려 검색 1위가 되면 그 곡이 고정되고, 보호 곡은 일반 풀에서 빠져
리랭커가 고칠 수 없다. dev 53건에는 그 경우가 없어서 측정에 나타나지 않는다.
회귀 테스트(`test_phonetic_protection_pins_a_wrong_song_too`)로 동작을 명시해 두었다.

## 권고

1. **phonetic 보호를 먼저 채택 검토한다.** 얻는 것이 분명하고 잃는 것이 없으며,
   발동 범위가 1곡으로 좁다. 다만 **53건 중 1건에서만 발동한 규칙**이라 이 측정으로
   일반화하기는 이르다. test split 23건으로 회귀를 한 번 더 봐야 한다 —
   거기서 한 번도 발동하지 않으면 그것은 안전성이 검증된 것이 아니라
   **표본이 없다는 뜻**이다. 그리고 이 세트는 전에 쓴 적이 있으므로 결과는
   새 일반화가 아니라 **추가 회귀 검증**으로 읽어야 한다.
2. **spread 생략은 채택하지 않는다.** q219를 못 고치고, m103과 q310을 맞바꾸며,
   재정렬을 77%에서 끈다. m103은 "현재 합성 계수에서 CE 기여가 검색 기여를 넘은"
   사례이므로, 손댄다면 임계값이 아니라 계수(`rerank_weight`/`spread_ref`) 쪽이다.
3. 두 규칙을 **같이 켠 조건은 재지 않았다.** phonetic 보호를 채택한 뒤 필요하면 잰다.

## 보호된 곡의 설명

phonetic 보호에 exact용 규칙(`lyrics_exact_priority`)을 재사용하면 설명이
"가사가 그대로 일치해 먼저 배치"로 시작한다. 음차는 **추정 표기**이고 비교도 표기
정규화 후에 하므로 두 번 틀린 말이다. 유형별 규칙으로 나눴다.

```
q219 정답 1위:
  음차 추정 표기의 가사 일치를 보호해 먼저 배치 (일반 후보 아래로 내려가지 않음)
  · 가사 구절 일치 경로 1위, 음차 추정 표기가 가사와 표기 정규화 후 일치 ×5.0,
    단서 확신도 0.85 (+0.0697) · …
  → 순서 규칙으로 배치(리랭커에 넘기지 않음)
```

| 규칙 | 문구 |
|---|---|
| `lyrics_exact_priority` | 기억한 구절이 가사와 일치해 먼저 배치 |
| `lyrics_phonetic_priority` | 음차 추정 표기의 가사 일치를 보호해 먼저 배치 |

## 주의

보호 규칙 판정은 `search_router.select_protected_lyric_ids()` **한 곳**에 있고,
서비스 라우터와 평가 스크립트가 같은 함수를 쓴다. 이 A/B를 위해 판정 위치를
옮겼으며(가사 경로 루프 → 보정이 끝난 후보 목록), **현행 조건의 숫자가 v0.11과
완전히 같음을 먼저 확인**했다(타이밍 열만 차이).
