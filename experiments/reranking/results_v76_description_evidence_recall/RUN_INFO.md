## 2. 선택 — "앨범 소개 원문 중 색인 문서에 없는 낱말" 보조 텍스트 경로

**해결할 일반 실패**: 질의가 곡이 놓인 맥락(출연·경연 프로그램, 원곡과 다시 부름, 참여 형태, 협업 구성 등)을 **일반어로** 서술하고, 곡 자료에서 그 일반어가 있는 곳은 멜론 앨범 소개 원문뿐인데, 색인에는 그 원문을 요약한 `album_summary`만 들어가 일반어가 빠진 경우.

**기존 경로가 실패하는 이유**: BM25는 문서에 없는 낱말을 맞힐 수 없고(일치 0), dense 문서에는 소개 원문도 요약도 없다. Context는 나무위키 사실(639곡)만 보고 `has_context_clue`일 때만 돈다. 작품명 보조 경로는 판정 통과(dev 22/176) → 모델이 작품명을 냄 → 그 이름이 원문에 글자로 있는 곡만 찾는다. 즉 "고유명을 알아낸 뒤 찾기"이고, 이름을 못 내거나(보류·판정 밖) 표기가 다르면 끝난다.

**기존 기능과 겹치는가**: 겹치지 않는다. 같은 필드를 읽는 유일한 경로(작품명 언급 조회)는 모델이 낸 이름의 **글자 포함 여부**를 보는 필터이고, 이번 경로는 **질의의 일반어 자체**로 원문을 검색한다(모델 호출 없음, 판정 규칙 없음). 두 번째 단계에서 기존 텍스트 검색을 곡 목록 안으로 제한해 다시 쓰는 방식은 작품명 보조와 같은 기반 함수(`song_id_filter` · `SearchService.search_text`)를 재사용할 뿐이다.

선택 조건 대조:

| 조건 | 이번 변경 |
|---|---|
| 질의 ID·정답 곡·정답 작품명에 의존하지 않음 | 입력은 질의 분석의 `korean_tags`와 코퍼스뿐 |
| 실제 자료의 근거 사용 | 멜론 앨범 소개 원문(수집된 자료) |
| 질의별 수작업 사전·정답을 알고 만든 설명 없음 | 낱말 목록·사전 없음. 규칙은 "원문 토큰 − 색인 문서 토큰" 하나 |
| 누락 정보를 구체적으로 설명 가능 | 곡마다 "색인 밖 원문 토큰" 집합으로 남는다 |
| 전체 코퍼스에 같은 규칙 | 5,143곡에 같은 규칙(소개 없는 270곡은 빈 문서) |
| 범위·비용 제한, OFF 가능 | 기본 OFF(가중 0이면 산출물도 읽지 않음), 보조 목록 ≤ 10곡, 질의당 Qdrant 조회 +1 |

후보를 여러 개 만들어 dev 점수로 고르지 않았다. 다른 묶음(표지·소리)은 §1에서 기존 자료로 풀 수 없다고 봤다(§9).

## 3. 구현 전에 고정한 설계

### 3-1. 산출물(별도 파일, 운영 자료 읽기 전용)

- 입력: `data/all_songs.jsonl`(읽기만). 곡마다 `metadata.album_description`을 `normalize_for_bm25`로 토큰화하고, **같은 곡의 `build_sparse_passage`(색인 문서) 토큰 집합에 없는 토큰만** 남긴다(중복 횟수 유지) = "색인 밖 원문 토큰".
- 설명 묶음: 설명 원문(앞뒤 공백 제거) sha256 앞 16자. 같은 앨범 곡들이 같은 묶음이 된다.
- BM25 통계(문서 = 곡의 색인 밖 토큰): 문서 빈도·평균 길이·문서 수. 소개 없는 곡은 문서에서 뺀다.
- 기록: 규칙 판 `desc_residual_v1`, 입력 jsonl sha256, `korean_bm25_tokenizer.py`·`passage_builder.py` 파일 sha256, kiwipiepy 판, 곡 수·문서 수·토큰 수, 산출물 자체 sha256(별도 manifest).
- 위치: `artifacts/description_aux/description_residual_v1.json.gz`(Git 제외 경로) + `…manifest.json`. 빌더 `python -m src.retrieval.description_aux build`(구현 때 모듈 하나로 합쳤다 — 측정 전 이름만 고침).

### 3-2. 질의에서 쓰는 것 · 쓰지 않는 것

- **쓴다**: `analysis.korean_tags`를 `normalize_for_bm25`로 토큰화한 고유 토큰 집합(텍스트 경로 기본 sparse 질의와 같은 원천).
- **쓰지 않는다**: 질의 원문 · 곡 제목·가수 단서(`song_title` · `artist_name` · 별칭 — 다른 앨범 소개에도 가수 이름이 흔하고, 식별 단서는 제목·가수 경로가 맡는다) · 가사 구절 · 영문 이미지/오디오 질의 · 작품명 해석 결과 · 재질문 답.

### 3-3. 발동 · 보류 · 오류

- 발동(모두 참): 보조 가중 > 0으로 런타임이 주입됨 · `force_weights` 없음 · `disable_boost` 아님(다른 보조 경로와 같은 조건) · **정확 가사 구절이 없음**(`_exact_lyric_terms` 비어 있음 — 텍스트 경로가 가사 전용 질의로 바뀌는 질의라 가사 보호 계약을 건드리지 않는다) · 질의 토큰 1개 이상.
- 보류(정상, 오류 아님): 근거 곡 0 → 상태 `no_evidence`. 근거 = **색인 밖 원문 토큰과 질의 토큰이 서로 다른 토큰 2개 이상 겹치는 곡**(`MIN_MATCHED_TERMS = 2` — 낱말 하나 일치는 "남자"·"사랑"처럼 수천 곡에 맞아 근거가 아니다). 두 번째 단계 결과가 비면 `no_aux_songs`.
- 판정 밖: `off`(주입 안 됨 — 기록 없음) · `not_triggered:<사유>`(`exact_lyric` · `no_query_terms` · `ablation`).
- 오류: 1·2단계 예외 → 상태 `failed:<예외 이름>`, 경로 실패 기록(`failed_paths`)에 남기고 **융합 목록은 손대지 않는다**(기존 결과와 같음). 산출물을 못 읽거나 지문이 틀리면 기동 오류(조용히 꺼지지 않는다).

### 3-4. 조회 · 융합 · 후보 수(값과 근거)

1. 1단계(메모리): 근거 곡을 BM25(Okapi, k1 = 1.2 · b = 0.75 — 텍스트 색인 `bm25_params.json`과 같은 값, idf = ln(1 + (N − df + 0.5)/(df + 0.5)))로 점수 매긴다. 설명 묶음 점수 = 묶음 안 근거 곡 점수의 최댓값. 묶음을 (점수 내림차순, 묶음 id 오름차순)으로 세워 **위 10묶음**(`GROUPS_K = 10` — 작품명 보조 목록 상한 `AUX_MAX_SONGS = 10`과 같은 값).
2. 2단계(Qdrant 1회): 그 10묶음의 근거 곡만으로 기존 텍스트 하이브리드 검색(`_search_text` — 같은 dense 문장·sparse 질의·`text_alpha`)을 `song_id_filter`로 제한해 부르고, **묶음마다 가장 앞에 나온 곡 하나**를 그 묶음의 대표로 쓴다(앨범 단위 근거가 같은 앨범 곡 여럿을 한꺼번에 올리지 않게). 보조 목록 순서 = 1단계 묶음 순위. 길이 ≤ 10.
3. 융합: 다른 보조 경로와 같은 자리(명시 단서 보조 `metadata` 다음, 작품명 보조 앞)에서 `가중 / (60 + 순위)`를 더한다. **가중 `DESCRIPTION_AUX_WEIGHT` 기본 0(꺼짐), 켤 때의 값 0.5**(작품명 보조 기본 가중과 같은 값 — 코퍼스 문장 근거 보조 목록의 기존 계약).
4. 그 뒤(명시 단서 보정 · 거절 곡 제외 · 절단 · 가사 보호 · 리랭킹 그룹 · 답변 보너스)는 기존 그대로. **최종 후보 30 유지.** 들어온/밀려난 곡은 작품명 보조와 같은 방식(보조 없이 같은 보정·제외·절단을 한 결과와 비교)으로 기록한다.

- 정답이 근거(서로 다른 질의 토큰 2개 이상 일치)에 든 질의 **5/51**: c602(소개 묶음 **14위**) · n011(63위) · t100(109위) · q110(110위) · t009(117위 — 같은 앨범 다른 곡의 일치). 나머지 46건은 정답 소개에 질의 토큰이 0~1개만 있거나 소개가 없다(n046 · n055 · t043 · t079 소개 없음).
- **설계 때 본 세 질의**: c602 — "경연"·"우승"이 맞았지만 같은 두 낱말 이상이 맞는 다른 앨범이 13묶음 더 있었다. c603 — 맞은 낱말 "프로그램" 하나뿐(질의 토큰 `경연·프로그램·리메이크·남성·보컬`, 소개는 "오디션 프로그램"·"원곡자"). t038 — 0개(질의 `오디션·듀엣·록·리메이크·드라마·ost`, 소개는 "라이벌 미션"·"두 남자"·"원곡"). 즉 **질의의 일반어와 소개 원문의 일반어도 서로 다른 낱말**이었다(오디션↔미션 · 리메이크↔원곡 · 듀엣↔두 남자). §1에서 "원문에 일반어가 있다"고 본 것은 맞지만, **그 일반어가 질의와 같은 낱말이라는 가정이 틀렸다** — 글자 일치(BM25)로는 이 차이를 넘지 못한다.
- 반대로 홍보 문체의 흔한 낱말 두 개(예: 보컬·감성·무대·데뷔)는 수백 곡에 맞아, 보조 목록은 대부분 근거가 약한 곡으로 찼다. 이 곡들이 후보 끝자리에 들어와 t044·c705의 정답을 밀어냈다(§3-5의 손실 경로 2·4가 그대로 나타났다).
- c602가 14위라는 사실로 묶음 수(10)를 늘리지 않는다(§3-4·§6 — 규칙을 찾은 질의로 값을 고르는 일이다).
