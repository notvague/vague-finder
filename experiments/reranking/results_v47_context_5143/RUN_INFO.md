#12의 Context 색인은 3,016곡 기준이라, 5,143곡 로컬에서는 Context 경로가 빈 결과를 냈다(results_v46 §4). 확장 곡(raw8)에 나무위키 수집을 돌리고 기존 곡 산출물과 합쳐 Context 색인을 만든 뒤, dev 176건의 **후보 단계**를 쟀다.
**리랭킹을 끄고 쟀다(Gemini 호출 없음)** — 10/13 밤 AI Studio 크레딧이 소진돼 리랭킹까지 재지 못했다. 최종 순위 · 봉인 test는 재지 않았다. 코드 변경 없음.

- 측정 코드: main `5e08e68` + v46 커밋(#55) — **v46과 같은 코드 · 같은 분석 캐시**(`results_v46_main_after_context/analysis_cache_*_dev_ctx.json`). 이 브랜치는 그 뒤의 main에서 파일만 더한 것이다
- 색인: v46이 쓴 기준 색인의 복사본 + Context 컬렉션 2개(`artifacts/qdrant_5143_context`). Text · Image · Audio는 v46과 같다
- `RERANKER_ENABLED=false` · `SEARCH_REFERENCE_YEAR=2026` · Context 설정은 #12 기본값(가중 0.5 · 작품명 배율 2.0 · 폭 100/100 · 후보 30)

## 결론

1. **Context를 켜면 후보가 2건 늘고 빠지는 것은 없다.** 후보 30 안 118 → 120(소리 경로를 끈 상태에서는 119 → 121)
2. **효과가 닿는 질의는 적다.** `context_clues`가 붙은 37건 중 후보 순위가 바뀐 것은 6건, 새로 든 것은 q203 · t071 두 건이다
3. 까닭은 자료 쪽이다. 그 37건 중 **정답 곡에 나무위키 사실이 있는 것은 11건뿐**이다(여담 없음 12 · 문서 없음 13 · 검토 필요 1)
4. **소리 경로 끄기와 겹치지 않는다.** 두 효과는 서로 다른 질의에서 나고, 함께 켜면 121이다

- **서비스 색인(`artifacts/qdrant`)에는 아직 올리지 않았다**

## 4. 이 숫자가 말하지 못하는 것

- **최종 순위.** 리랭킹을 껐다. 후보에 든 2건이 10위 안까지 가는지, Context 근거가 리랭킹에 어떻게 작용하는지는 모른다
- **지금 main.** 측정 뒤 main에 #54 · #56 · #57이 들어왔다. #56은 모달리티 규칙과 Context 후보 처리를 고쳐 분석 캐시가 다시 어긋난다 — 크레딧이 들어오면 캐시부터 다시 만들어 재야 한다
- 평가 질의는 Context를 겨냥해 쓴 것이 아니다. 배경지식 질의만 모은 정현의 세트(#12)와는 다른 질문에 답하는 숫자다
- 검토 필요 544곡을 정리하면 사실 있는 곡이 더 늘 수 있다

색인을 다시 만드는 순서(곡 원본과 ZIP이 있어야 한다):

```
# 1) 확장 곡 수집 — 같은 명령을 되풀이하면 이어받는다
venv/bin/python -m src.crawler.scripts_py.backfill_namuwiki_context --data-dir <raw8> --cache-dir data/context --artifact-dir artifacts/context
# 2) 기존 곡 산출물(ZIP의 artifacts/context/songs)과 합치고 manifest 재발행 — 로컬 스크립트 data/crawl_batches/merge_context_artifacts.py
# 3) 임베딩 · BM25 · 적재
venv/bin/python -m src.embedding.cli.embed_context_dense
venv/bin/python -m src.embedding.cli.fit_context_bm25
venv/bin/python -m src.vector_db.cli.qdrant_load_context --qdrant-path <색인 폴더>
```
