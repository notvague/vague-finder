## 왜 m402 발라드·솔로는 남는가 — 후보 순서 (파일 근거)

**대조 실험은 `new_only_r1/clarify_turns.csv`에 이미 있다.** m402(목표 곡 67169) 거절 뒤 2턴에서 `flow:reject`(답 없음)와 `flow:oracle`(발라드)을 비교하면:

| `new_only_r1` 2턴 | 프롬프트의 답변 블록 | 후보 30곡 | 정답 후보 순위 | 다른 것 | 리랭킹 뒤 정답 |
|---|---|---|---|---|---|
| `flow:reject` | 없음 | 집합 동일 | 7 | — | 7위 |
| `flow:oracle` 발라드 | **없음**(①에서 확인용이라 빠짐) | 집합 동일 | 7 | 나머지 후보 10자리의 순서 | Top-10 밖 |

프롬프트 내용이 같고 후보 집합·정답 위치가 같은데 **다른 후보들의 순서만으로** 결과가 7위 ↔ 밖으로 갈린다. 답변 보너스(`apply_answer_bonus`, ×3.0)가 정답과 경쟁곡에 똑같이 붙어 정답 순위는 그대로지만 경쟁곡끼리의 순서를 바꾸기 때문이다.

손실 4건은 모두 **거절 뒤 조건**이므로 그 조건에서 답마다 후보 순서가 얼마나 바뀌는지 다시 셌다 — `candidate_order_after_reject.csv`. 생성 스크립트는 같은 폴더의 `candidate_order_after_reject.py`(라우터 `search(use_rerank=False)`를 `base_r1`의 첫 검색 Top-10 제외로 돌려 답 없음과 비교, 답은 하네스와 같은 `oracle_value`, Gemini 호출 없음):

```bash
venv/bin/python experiments/reranking/results_clarify_v10_corrections/candidate_order_after_reject.py
```


| 거절 뒤 재검색 | 답 | 자리 바뀐 후보 수 (30 중) | 정답 후보 순위 (없음 → 답) | 리랭킹 뒤 (base → 해당 변형) |
|---|---|---|---|---|
| m402 | 남성 (같은 값) | 3 | 7 → 7 | 밖 → **7위** (①) |

| c603 | 록/메탈 (새 정보) | 22 | 22 → **1** | 1위 |

(첫 검색 조건의 수치 — 남성 0 · 발라드 0 · 솔로 4 · 2000년대 26 — 는 이 표와 다르다. 손실과 무관한 조건이라 더 쓰지 않는다.)

순서가 결과에 들어가는 길은 둘이다. (가) 프롬프트의 `retrieval_rank` 사전순위 (나) 합성식 — 최종 점수 = 검색 순위 점수 15% + LLM 85%(`gemini_listwise_reranker.py` `_fuse`, `retrieval_norm`; 15%는 질의 확신도가 0.55 이상일 때이고, 낮으면 LLM 가중치가 줄어 검색 순위 몫이 커진다). 보너스는 둘 다 바꾼다.
같은 후보에서 순서만 바뀌어도 결과가 달라지는 것은 재질문만의 문제가 아니라 **listwise 전반의 성질**이다.

## 읽는 법

- 가설 ①("확인용 답을 more reliable로 넘긴다")은 **m402 남성 1건**을 설명한다. 보너스가 순서를 3곳 바꿔도 답변 문구만 빼면 7위를 지킨다.
- **①은 거래다.** 확인용 답이 도움이 되는 사례가 있다 — v09 dev q205(분석 남성, 거절만 6위 → 남성 답 2위), 이번 m402 `flow:oracle` 3턴(발라드+남성 → 1위, ①에서는 두 답이 빠져 4위). 둘 다 Top-10 안에서 순위만 내려가므로 **"Hit@10 손실 0" 기준으로는 안 잡힌다.** dev 비교에는 질의별 순위와 Hit@1·MRR을 함께 봐야 한다(`results_clarify_v09/compare_clarify.py`에 순위 표 추가). ①은 dev에서 m402 남성을 고치고(Hit@10 +1) q205·m402 flow에서 순위를 잃는 거래로 예상된다.
- 가설 ②("type 슬롯 괄호 문구")는 **c603 솔로 1건**을 설명한다. 보너스가 29곳을 바꿔 정답이 22 → 14위로 올라오는데도 base는 밖, ②는 3위다. m402 솔로(8곳, 7 → 7)는 ②로도 안 된다.
- **나머지 2건(m402 발라드·솔로)의 원인은 리랭커 입력 순서의 민감도다.** 프롬프트 수정으로는 닿지 않는다. 손볼 곳은 (a) 답변이 있을 때 리랭커에 넘기는 후보 순서를 보너스 전 순서로 고정(보너스는 최종 합성에만) 또는 (b) 프롬프트에서 사전순위 비중 낮추기.
  **(a)는 합성식에서도 보너스가 빠지므로, 보너스 덕에 정답이 올라간 경우(m402 2000년대 7 → 3, c603 록/메탈 22 → 1, c603 2010년대 22 → 7)의 이득이 사라질 수 있다.** (a)를 재면 이 세 경우를 측정 항목에 넣는다.
- **①은 틀린 답도 뺀다.** 분석이 틀렸고 틀린 답이 그 분석과 같으면 "확인용"으로 분류된다. v09·test_v06의 flow 답을 `answer_confirms_analysis`로 돌리면(`classify_rows_by_switch.py`):

  | | ①이 빼는 맞는 답 | ①이 빼는 틀린 답 |
  |---|---|---|
  | dev | m402 남성·발라드, m403 발라드, q112 랩/힙합, q205·q208·q210 남성 | **c701 남성, c705 남성** |
  | test | c703 여성, m401 혼성 | c704 여성, q118 여성·발라드 |

  동작은 일관된다(질의에 이미 있는 내용을 다시 말한 답은 새 정보가 아니다). 읽을 때 주의할 점은 c701·c705가 v09에서 맞는 답으로 +2를 얻은 바로 그 질의라는 것이다 —
  분석(남성)이 틀렸고 맞는 답(여성)이 바로잡는다. 그 두 질의의 `flow:noisy`가 dev 57 비교에서 바뀌면 변동이 아니라 ①의 효과다.
- 두 질의 결과만으로 기본값을 바꾸지 않는다.
