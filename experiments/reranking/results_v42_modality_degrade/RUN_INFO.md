# results_v42 — 모달리티 경계만 어긴 응답은 그 모달리티만 내려놓기 (2026-10-12)

규칙과 모델이 한 모달리티에서 어긋나면 분석 **전체**가 규칙 폴백이 되던 구조를 고쳤다(`results_v40`·`v41`이 "남는 위험"으로 적어 둔 것).

- 워크트리 `../vague-finder-modality-fix` · 브랜치 `fix/analysis-modality-degrade` (main `7bf603d`, #45 병합 뒤)
- 코드: `src/retrieval/modality_queries.py` · `src/retrieval/query_analyzer.py` · `src/backend/schemas/query.py`, 테스트 `tests/test_modality_degrade.py`(22건). 전체 1,946 통과(기존 macOS `/tmp` 1건 제외)
- 측정 조건은 v38~v41과 같다(5,143곡 · listwise 기본 · AI Studio `api_key` · 리랭킹 실패 0). 분석 프롬프트는 그대로
- 이 워크트리의 Qdrant 사본은 10/11 적재분이다 — 10/12의 5곡 메타데이터 수정(#45) **전**이라 v39·v41 기준선과 같은 색인이다

## 1. 문제

`apply_modality_query_safeguards`는 네 경우에 예외를 낸다.

| | 누락 (규칙은 단서가 있다는데 모델이 프롬프트를 안 냄) | 누출 (프롬프트에 다른 모달리티 낱말) |
|---|---|---|
| 표지 | `album-art visual clue requires image_english_query` | `image_english_query contains audio-only wording` |
| 소리 | `explicit auditory clue requires audio_english_query` | `audio_english_query contains visual-only wording` |

분석기는 정정을 붙여 3회까지 다시 묻고, 그래도 어긋나면 `_fallback(query)` — 모델이 낸 태그·가수·성별·장르·가사 단서를 전부 버리고 규칙만으로 만든 분석(`confidence=0`)을 썼다.
v10 첫 측정에서 dev 60건 중 4건이 이렇게 떨어졌고(전부 규칙 오탐), #42·#43으로 규칙을 고친 뒤에도 dev 176건 중 n025 한 건이 남아 있다.

## 2. 바꾼 것

**재시도는 그대로 한다.** 3회가 다 실패했을 때(또는 분석 예산을 다 썼을 때), 모달리티 경계**만** 어긴 응답이 있으면 그것으로 분석을 만든다(`QueryAnalyzer._degrade`). 여러 번 어겼으면 마지막 응답을 쓴다.

| 어긴 방식 | 처리 | 이유 |
|---|---|---|
| 누락 | 그 경로를 **끈다**(프롬프트 없음, 가중 0 → 나머지로 재정규화) | 정정을 받고도 안 낸 것이라 모델 판단을 따른다. 규칙 프롬프트로 채우면 규칙이 틀렸을 때 그 오염이 검색에 들어간다 |
| 누출 | **규칙이 만든 프롬프트**로 바꾼다. 규칙이 만들 것이 없으면 끈다 | 단서가 있다는 데는 규칙과 모델이 같다. 못 믿는 것은 문장뿐이다 |

- 다른 모달리티와 나머지 필드는 손대지 않는다. 가중은 모델 값을 기존 정규화(`_normalize_weights` · 상세 소리 묘사 하한)에 그대로 태운다
- 내려놓은 모달리티는 `QueryAnalysis.degraded_modalities`(새 필드, 기본 빈 목록)에 남는다. 후처리가 넣는 값이라 모델 응답이 실어 보내도 덮는다. 이 필드가 없는 옛 캐시·`prior_analysis`는 그대로 읽힌다
- 살릴 응답이 없으면(통신 오류·JSON 오류뿐이거나 다른 필드까지 스키마를 어김) 전처럼 규칙 폴백이다
- `ModalityQueryValidationError`에 `modality`·`kind`를 달았다. `apply_modality_query_safeguards`의 기본 동작(예외)은 그대로이고 `degrade=True`일 때만 위 처리를 한다

## 3. 통과한 응답의 분석은 그대로다 (`reapply_safeguards.py`)

저장된 분석(폴백 제외)에 지금 후처리를 다시 적용했다 — v06 dev·test, v09 dev·test, v10 dev, v40·v41의 재분석 캐시. Gemini·검색 없음.

- 351건 중 349건이 그대로(프롬프트·가중·`has_visual_clue`), 기본 길과 내려놓는 길의 결과가 같고 `degraded_modalities`는 전부 빈 목록
- 남은 2건은 같은 질의 n057(v09 dev 캐시 두 벌)이다. #42 때부터 있던 항목이다(옛 코드로도 `audio_english_query` 보강이 달라진다)

→ **분석이 바뀌는 질의는 dev 176건(v06 57 · v09 59 · v10 60) 중 폴백으로 남아 있던 n025 하나다.** v39·v41 기준선의 나머지 175건은 다시 잴 것이 없다.
후처리 코드가 바뀌어 `postprocess_sha`는 달라진다. 저장된 분석은 위와 같이 그대로라 `--reuse-despite-drift`로 계속 쓴다.

## 4. n025 — 실제 사례 (`run.sh`, 2회 동일)

> 술자리 게임 이름을 그대로 후렴에서 반복하는 노래, 걸그룹 멤버가 외국 남자 팝스타랑 같이 불렀어. 진짜 어딜 가나 나왔던 것 같아 (정답 `38120327`)

모델이 소리 프롬프트에 "pop star"를 쓰고 누출 검사가 `star`를 시각 낱말로 읽는다. 정정을 줘도 세 번 다 같다(`build_cache.log`).

| 분석 | 소리 프롬프트 · 가중 | 텍스트 경로 | 소리 경로 | 후보 순위 | 최종 |
|---|---|---|---|---|---|
| **전** — 규칙 폴백 (`before`) | 없음 · text 1.0 | 1위 | — | **15** | 1위 |
| **후** — 소리만 규칙 프롬프트로 (`degrade`, 채택) | `An audio track with two duet vocalists.` · text 0.7 / audio 0.3 | 2위 | 1,489위 | **2** | 1위 |
| 대조 — 소리 끔 (`audio_off`) | 없음 · text 1.0 | 2위 | — | **1** | 1위 |

- 후보 순위가 15 → 2로 오른 것은 살린 분석 덕이다 — `performance` 보조 경로 1위, 가산 `vocal_gender_match +0.0164` · `performance_clues +0.0221`(`candidate_drop_n025_*.csv`). 폴백 분석에는 성별·편성 단서가 없었다
- 최종 순위는 셋 다 1위라 **v09 dev 숫자(Hit@1 28 · Hit@10 38, v39)는 그대로다**
- 규칙이 만든 소리 프롬프트는 이 질의에서 쓸모가 없었다(소리 경로 1,489위). 끈 쪽이 후보 1위로 한 칸 높다
- 분석 시간은 그대로 약 8초다(3회 호출). 이번에는 재시도 횟수를 건드리지 않았다(§7)

## 5. q115 — 누출을 규칙 프롬프트로 바꿀지, 끌지 (`run_q115.sh`, 가정 실험 · 2회 동일)

n025에서는 끄는 쪽이 한 칸 높았다. 소리 묘사가 중심인 질의에서는 어떤지 보려고 q115(v06 dev)로 가정 실험을 했다. q115는 실제로 이 일이 있었던 질의다
(results_v36 캐시 생성 로그: "… in the background" → `background`로 3회 거부). 지금 저장된 분석은 통과한 것이라, 프롬프트 끝에 "in the background"를 붙여 같은 상황을 만들었다(`make_q115_leak_variants.py`).

> 반주가 거의 피아노 하나뿐인데 남자가 호소하듯이 부르는 발라드였어. 오케스트라 같은 게 뒤에서 조금씩 깔렸던 것 같고 최근 곡이야 (정답 `31829536`)

| 분석 | 텍스트 경로 | 소리 경로 | 가산 뒤 순위(전수) | 후보 30 |
|---|---|---|---|---|
| 저장된 분석(통과) | 359 | 236 | 105 | 밖 |
| 예전 동작 — 규칙 폴백 | **40** | 263 | 25 | 밖(보정 뒤 절단) |
| **채택 — 소리만 규칙 프롬프트로** | 359 | 295 | 102 | 밖 |
| 대조 — 소리 끔 | 359 | — | 128 | 밖 |

- 넷 다 후보 밖이라 최종 결과는 같다(Hit 0). 규칙 프롬프트는 모델 프롬프트와 비슷한 깊이를 낸다(소리 295 vs 236, 가산 뒤 102 vs 105). 끄면 128로 더 밀린다
- → 누출은 **규칙 프롬프트로 바꾼다**를 유지한다. 근거는 이 한 건의 약한 차이(102 vs 128)와 n025의 한 칸 손해(2 vs 1)뿐이라, 사례가 더 모이면 다시 본다
- **별개의 관찰:** 이 질의는 규칙 폴백의 텍스트 경로(40위)가 모델 분석의 텍스트 경로(359위)보다 훨씬 낫다. 살린 분석이 폴백보다 항상 좋은 것은 아니다 — n025는 반대였다(15 → 2). 소리 묘사 질의에서 모델 분석이 텍스트 경로를 어떻게 바꾸는지는 다음 작업(소리 묘사 질의)에서 본다

## 6. 누락 쪽 — 실제 Gemini로 본 동작 (세트 밖 문장, 순위 측정 아님)

dev 176건에는 누락으로 떨어지는 질의가 남아 있지 않다(#42·#43이 규칙을 고쳤다). 규칙이 아직 틀리는 문장을 만들어 실제 Gemini로 분석했다.

| 문장 | 규칙이 읽은 것 | 전 (규칙 폴백) | 후 |
|---|---|---|---|
| 앨범 내고 별 반응 없다가 역주행한 남자 아이돌 노래, 가사에 사랑해가 계속 나와 | "별" + "앨범" → 표지 | 표지 프롬프트 `Album cover with stars.` · 표지 가중 0.5 · 성별·태그 없음 | 표지 끔 · text 1.0 · 성별 남성 · 태그(남자아이돌·역주행·사랑해) |
| 비 맞으면서 우는 장면이 유명한 드라마 OST 앨범에 실린 남자 가수 노래 | "비" + "앨범" → 표지 | text 1.0 · 성별·장르 없음 | 표지 끔 · 성별 남성 · 장르 발라드 |
| 해 뜰 때까지 놀자는 가사의 여자 그룹 노래 앨범 이름이 숫자였어 | "해" + "앨범" → 표지 | text 1.0 · 성별 없음 | 표지 끔 · 성별 여성 |

- 셋 다 모델이 세 번 모두 표지 프롬프트를 내지 않았고(모델이 맞다), 분석은 `degraded_modalities=["image"]`로 살아났다
- 첫 문장은 예전이면 "별 그림 표지"를 표지 가중 0.5로 검색했다
- "하얀 원피스 입은 여자 이미지였어"(#43이 적어 둔 위험 문장)는 모델이 표지 프롬프트를 내서 검증을 통과한다 — 내려놓기까지 가지 않는다

## 7. 하지 않은 것 · 남는 것

- **재시도 횟수.** 내려놓게 되는 질의는 여전히 3회 호출(약 8초)이다. 남아 있는 로그로는 정정이 2번째 시도에서 통한 것이 2건(소리 누락), 2번째도 실패한 뒤 3번째에 통한 것은 0건(누출 7 — 옛 로그 5 · 이번 2, 누락 — 이번 3)이다. "같은 위반이 두 번 이어지면 세 번째는 묻지 않는다"로 약 2.5초를 줄일 수 있지만 표본이 작아 이번에 넣지 않았다
- **누출 검사 낱말 오탐**(n025 "pop star", q115 "background")은 그대로다. 고치면 이 두 질의는 내려놓기 없이 모델 프롬프트를 그대로 쓴다
- **한 글자 명사 오탐이 남아 있다** — "별 반응", "비 맞으면서", "해 뜰 때"가 "앨범"과 함께 표지 단서로 읽힌다(§6). 이제 분석 전체를 잃지는 않지만 3회 호출은 든다
- 라우트의 벽시계 상한(`routes/search.py`의 `_analyze`)에 걸려 끊긴 경우는 전처럼 규칙 폴백이다 — 분석기 밖에서 끊겨 살릴 응답을 넘겨받지 못한다
- 근거 패널·실행 기록에는 "일부 모달리티를 내려놓음"을 싣지 않았다. `analysis_fallback`은 거짓으로 남는다(규칙 폴백이 아니므로). 필드와 서버 로그에만 있다
- 봉인 test(v09 38 · v10 42)는 재지 않았다
