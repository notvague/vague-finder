### 1-2. 고친 것(실제 결함 1)

**재질문 답이 보조 경로에 반영되지 않았다.** 라우터는 답(`answers`)을 검색 질의에 넣지 않고 후보 재정렬 보너스로만 쓰며(q200 회귀), 검색 뒤 질의 속성을 다시 보는 자리(가사 exact 묶음 정렬)에서는 `analysis_with_answers`로 정정된 사본을 쓴다. 그런데 v51의 `_build_attribute_filter(analysis)`는 **최초 분석**으로 필터를 만들었다 — 사용자가 "남성"을 "여성"으로 고쳐도 2턴 보조 검색은 남성(+혼성) 30곡을 더 불러와 정정을 이 경로에서만 무시했다. 서비스(`routes/search.py` → `search_router.search(answers=…)`)와 평가기(`evaluate_clarification.run_search`)가 같은 입구라 둘 다 해당했다.

- 수정: `search_router.search`에서 필터만 `analysis_with_answers(analysis, answers)`로 만든다. 텍스트 질의(dense/sparse)는 원래 분석 그대로다. 답이 없으면 같은 객체라 1턴 동작은 그대로. 출생 연도 답은 라우터 입구의 `apply_birth_year_answers`가 이미 시기 창을 넣으므로 그 창이 필터의 시기 축이 된다
- 회귀 테스트(`tests/test_attr_filter_path.py`, 13 → 22건): 성별 정정(`test_answer_corrects_the_filter_condition`, 원본 분석 불변 확인) · 모름 답(`test_skipped_answer_leaves_the_filter_as_is`) · 장르/형태/연대 답이 축이 됨 · 출생 연도 답이 시기 축을 염(1990 + 중학교 13~15 ± 1 = 2002~2006) · 가중 0이면 답이 있어도 아무것도 안 함
- 서비스에서 실제로 묻는 슬롯은 성별·장르(+출생 연도)뿐이고 시기 축은 최초 분석에 이미 있어야 열리므로, 이 결함이 닿는 경우는 "시기 창이 있는 질의에서 성별/장르 답" 또는 "생애 단계 질의에서 출생 연도 답"이다. §5의 2턴 측정은 **고친 코드**로 했다

### 1-3. 평가기 추가(`evaluate_clarification --policies flow`)

한 번 답변 정책(reject_only · oracle:* · noisy:* · rule:*)을 돌리지 않고 최초 검색 + 서비스 2턴 흐름(`flow:reject/skip/oracle/noisy`)만 잰다 — 이번 비교 대상이 서비스 경로뿐이고 호출을 절반 아래로 줄이기 위해서다. 돌리지 않은 정책의 행은 **채우지 않는다**(채우면 잰 것처럼 보인다). `intervention_ids_from_detail`은 `flow:reject`가 실제로 돈 질의도 개입 대상으로 읽는다(`--resummarize` 호환). 기본값 `all`은 그대로다.
