# 전달 안내(보관자가 직접 보낸다 — 에이전트는 보내지 않는다)

## 1. 부탁 전에 묻기(라벨러·확인자 후보 각각)

> 작품명 라벨 22건(30분~1시간)을 부탁하려고 해요. 드라마·예능·영화를 아는 분이면 됩니다. 시작 전에 네 가지만 답해 주세요. 이미 봤어도 괜찮고, 그대로 기록만 해요.
> 1. 작품명 해석 실험(v71·v72) 결과나 PR #85·#86, 에이전트 보고를 본 적 있나요?
> 2. dev 평가 질의의 정답 곡을 아세요? (질의를 직접 썼거나 평가 CSV를 봤는지)
> 3. 저장소 v67 진단 폴더(작품명 목록·실패 검토표)를 본 적 있나요?
> 4. v70~v72 검색 순위·Hit 결과표를 본 적 있나요?

답은 README §2 표에 적는다. 1·3·4 중 하나라도 "예"면 그 사람의 라벨은 독립 라벨과 따로 센다. 그래도 라벨 자체는 받는다.

## 2. 라벨러에게 보낼 것

`private/packet/labeler/` 안의 **두 파일만** 보낸다.

- `work_label_sheet_labeler.csv`
- `LABELER_GUIDE.md`

> 질의 22개를 보고, 쓴 사람이 어떤 작품(드라마·예능 등)을 떠올렸는지 적어 주세요. 안내문에 칸 설명이 있어요. 문장만으로 정할 수 없으면 "판단불가"가 맞는 답이에요. 저장소·평가 자료·실험 결과는 보지 말아 주세요. 다른 사람과 답을 맞춰 보지도 말아 주세요. 다 채우면 이 파일만 저에게 보내 주세요.

## 3. 확인자에게 보낼 것(있으면)

`private/packet/checker/`의 두 파일. 라벨러의 결과는 보내지 않는다. 안내 문구는 2와 같다.

> 다른 분도 같은 22개를 따로 보고 있어요. 서로 맞춰 보지 말아 주세요.

## 4. 보내지 않는 것

`private/`의 다른 파일(`item_map.csv`·`source/`·`frozen/`·`stage2/`·`name_pairs.csv`), README, v71·v72 결과 폴더, 저장소 링크.

## 5. 받은 뒤

1. 받은 파일을 `private/returned/`에 둔다.
2. `check`를 돌린다. 오류가 있으면 형식만 되묻는다(예: "L07 상태 칸 값이 네 가지 중 하나가 아니에요"). 내용 힌트는 주지 않는다.
3. 오류가 없으면 `freeze`로 고정한다. 확인자 표가 오면 2단계 전에 고정한다.
