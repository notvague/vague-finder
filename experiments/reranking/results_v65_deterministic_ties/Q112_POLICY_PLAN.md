# 후속 계획 — 성별 답 뒤 장르 조건 제외(D conditional)의 일반 규칙과 독립 평가 (이번 v65에서는 코드 변경 없음)

작성 2026-10-17. v64 §7-② 결함의 후속이다. **이번 동점 수정에는 섞지 않았다.** D는 OFF(`ATTR_FILTER_WEIGHT=0`)이고 이 계획도 D 활성화를 전제하지 않는다.

## 1. 알려진 사례(재현 사례이지 평가 자료가 아니다)

| 사례 | 흐름 | 현재 정책(`_attr_genre_decision`, conditional) | 결과 |
|---|---|---|---|
| q112(v06 dev) "힙합 그룹 … 2000년대 중후반" | 1턴: 장르(힙합) 있음 · 성별 없음 → `no_gender` → 장르 **넣음**. 2턴: 성별 답 "남성"(정답 곡도 남성) | 성별 조건이 생기면 → `gender_condition` → 최초 장르 **뺌** | 필터가 넓어져 정답이 보조 상위 30 밖 → 1턴 후보 2위가 2턴 후보 밖(v64 §5-5, 가짜 모델·필터 재구성으로 확인) |
| t053(v10 dev) "… 밴드 록 … 2000년대 중반" | 같은 모양(`no_gender` + 장르 있음). 2턴 성별 답이 오면 같은 분기 | 같음 | 미측정(v54 2턴 평가는 v06·v09만, v10은 2턴 평가기 미지원) |

q112·t053은 이 흐름을 재현하는 **계약 시험 사례**로만 쓴다. 이 둘이 살아나는지로 정책을 고르지 않는다. dev 176·v10 test 42(열림)로 재튜닝하지 않는다.

## 2. 일반 규칙을 정하기 전에 나눠야 할 경우

정책 후보 "1턴에 장르로 연 필터는 성별 답이 와도 장르를 유지"는 **후보**다. 아래 경우를 함께 다루지 못하면 채택하지 않는다.

| # | 경우 | 단순 보존(장르 유지)의 위험 | 정해야 할 것 |
|---|---|---|---|
| ① | 성별 답이 최초 단서와 **충돌하지 않음**(q112: 힙합 + 남성) | 없음 — 조건이 하나 늘 뿐 | 성별은 "추가 조건"인가, conditional이 장르를 뺀 원래 이유(v54: 장르 기억 불일치 손실)와 어떻게 맞추나 |
| ② | 사용자가 **장르를 명시적으로 고침**(재질문 장르 답, 다른 장르) | 옛 장르를 유지하면 틀린 조건이 남는다 | 현재 규칙대로 마지막 장르 답이 최초 장르를 대체(`_answered_genre`) — 유지 |
| ③ | 성별 답이 최초 질의와 **충돌**(질의 "여자 아이돌 … 댄스" + 답 "남성") | 장르는 맞아도 성별 기억이 틀렸을 수 있고, 장르 기억도 같이 의심해야 할 수 있다 | 충돌 판정 규칙(질의의 성별 표지 vs 답)과 그때 장르를 둘지 — 규칙만, 임계값 없음 |
| ④ | **답 순서**(장르 답 뒤 성별 답, 성별 답 뒤 장르 답, 같은 칸 여러 번) | 순서에 따라 결과가 달라지면 재현이 안 된다 | 각 칸은 마지막 답이 이기고, 장르 축 판정은 답 집합의 최종 상태로만 정한다(순서 독립) |
| ⑤ | **거절 곡**(1턴 결과를 "아니에요"로 거절한 뒤 2턴) | 이전 후보를 무조건 보존하면 거절 곡이 돌아온다 | 거절 곡 제외는 필터 정책보다 앞선다(현 계약 유지). "후보 보존"을 장르 유지와 섞지 않는다 |
| ⑥ | "모름"(skipped)·빈 답 | 정보 없음을 조건으로 바꾸면 안 된다 | 현재 규칙 유지(건너뜀) |
| ⑦ | 장르가 등록 장르로 안 바뀌는 말(체감 장르) | 조건이 되지 않으니 유지·제외가 무의미 | 판정 사유에 그대로 남긴다(`had_genre_condition`) |

## 3. 시험의 구분

- **합성 계약 시험**(코드 PR에 포함): ①~⑦ 각각을 `_attr_genre_decision`·`_build_attribute_filter_with_policy` 단위로 — 입력(분석·답 목록) → 장르 축 판정·필터 모양. q112·t053의 실제 분석 캐시를 입력으로 쓰는 시험도 넣되, "정답이 후보에 남는다"를 단언하지 않는다(그건 품질이다). 답 순서를 바꿔도 같은 판정인지(④), 거절 곡이 결과에 없는지(⑤).
- **독립 품질 평가**(별도 실행): 아래 §4의 새 자료로만. 합성 시험 통과를 품질 근거로 쓰지 않는다.

## 4. 새 독립 1·2턴 자료

| 항목 | 계획 |
|---|---|
| 수집 | 팀이 새로 쓴 질의(기존 dev 176·v09/v10 test와 겹치지 않음, 같은 곡이라도 새 문장). 단서를 일부러 적게(기존 원칙) 쓰고, 작성자는 파이프라인 산출물(태그·요약)을 보지 않는다(metadata·cover만) |
| 대상 비율 | 보조 경로가 열릴 질의(시기 창 + 장르/성별/형태)를 충분히 — 예: 60건 중 30건 이상. 성별 표지가 없는 장르 질의(q112형)와 성별 표지가 있는 질의(충돌 ③ 사례 포함)를 나눠 담는다. 비율은 수집 전에 정하고 결과를 보고 바꾸지 않는다 |
| 2턴 답 | 질의마다 작성자가 **사전에** 답을 적는다: 맞는 성별 / 틀린 성별 / 장르 수정 / 모름 / 1턴 결과 거절(정답이 아닌 곡). 평가기가 질문을 하지 않는 질의(1턴 발견)는 2턴 흐름을 강제로 만든 별도 항목으로 따로 센다(v54에서 q112가 빠진 이유) |
| 라벨 | 정답 곡 id + 허용 정답 규칙은 기존과 같게(엄격/확장 분리). 성별·장르 라벨은 metadata 기준 + 사람이 확인 |
| 분할 | dev(정책 비교용) / test(봉인, 최종 1회). 같은 곡·같은 작성자의 변형 질의는 같은 분할에 둔다(누출 방지). 분할은 수집 직후 무작위 시드로 고정하고 시드를 기록한다 |
| 누출 방지 | 정책 후보를 dev에서 정한 뒤 test를 연다. test 결과로 다시 고치지 않는다. 분석 캐시는 새 자료로 한 번 만들고 지문을 기록한다(프롬프트 불변) |
| 비교 | A(OFF) · D(conditional 현행) · D′(후보 규칙) 각 2회 이상, 같은 캐시·색인·**동점 수정 뒤 코드**(v65)·같은 모드. 1턴·2턴을 따로, 2턴은 답 종류(①~⑥)별로 얻음/잃음 |
| 비용 | 실행 전에 호출 수(1턴 + 2턴 리랭킹)와 단가로 따로 산정해 승인받는다(이 문서는 예산을 정하지 않는다) |

## 5. 하지 않을 것

- q112 하나를 살리려고 규칙을 고르거나, 이전 후보를 무조건 보존하는 규칙을 넣지 않는다(②·⑤에서 틀린 조건·거절 곡이 남는다).
- 이번 동점 수정 PR에 정책 변경을 섞지 않는다. D 활성화 판단(v64 판단서: 증거 부족 → OFF)은 §4 결과 뒤에 다시 한다.
