### 1-4. 실행 순서·한도

1. **오프라인(모델 호출 차단)**: A1 → B1 → B2 → A2, 순차. 리랭커 호출 자리(`_generate`)는 **결정적 가짜 응답**(입력 순서 그대로의 정상 JSON)을 돌려준다 — 프롬프트는 실제로 만들어지고 sha256만 남긴다. Gemini 클라이언트 생성은 막혀 있다.
2. **실제 Vertex**: 오프라인이 유효(완료·건수·반복 동일)하고 예산 통제 자체 검사가 통과하면 같은 조건으로 A1 → B1 → B2 → A2, 순차(동시 실행 없음). 모델 응답 캐시는 이 코드에 없다(리랭커에 응답 캐시 없음 확인) — 네 실행은 독립 호출이다. 과거 저장 응답을 섞지 않는다.
3. 한도: 신규 모델 비용 **$10**(예약 기준), SDK HTTP 시도 **1,200회**(실패·재시도·무료 countTokens 포함), 작업 6시간(신규 호출 마감 06:20 KST — 그 뒤 분석·보고). 어느 한도든 닿으면 정지하고 부분 결과를 보고한다. 예산이 모자라면 완결된 A/B 쌍을 먼저 확보하고 반복을 시작하지 않는다. AI Studio·Claude 우회 없음.
4. 단가: `gemini-3.1-flash-lite` 입력 $0.25 · 출력(thinking 포함) $1.50 /100만 토큰 — Google 공식 Gemini API 가격표(https://ai.google.dev/gemini-api/docs/pricing, 2026-10-17 01:2x 확인). Vertex 가격 페이지는 스크립트로 본문이 읽히지 않았다(v50과 같음, 집계 사이트의 Vertex 표기는 같은 값). 최대 출력 65,536토큰(Vertex 모델 문서). 크레딧이 적용돼도 0원으로 세지 않는다. 캐시 토큰 할인은 적용하지 않는다(보수적).
5. 예약·정산(`v63_budget.py`, HTTP 시도 단위): 보내기 전 `요청 본문 글자 수 × 입력 단가 + 65,536 × 출력 단가`를 예약, 응답 `usageMetadata`로 정산, 사용량을 모르는 실패·취소·시간 초과는 **예약액을 미확인 비용으로 남김**. 401·403·결제/권한 400은 1회로 정지(재시도 없음), 연속 실패 5회·누적 실패 20회면 정지. 일시 장애 재시도는 서비스 리랭커의 기존 계약(공유 30초 안 최대 3회)만.

### 1-5. 분석 기준 (결과를 보기 전에 고정)

1. **정확성**: B의 하이브리드 호출이 전부 독립 정확 합산 기준(`exact_hybrid.ExactHybridReference`, v61 — 전체 벡터 scroll + f64 내적)과 같아야 한다(집합·점수 허용 오차 1e-4·동점 묶음 밖 순서). A는 기준과 다른 호출 수·곡을 센다. 이것은 품질과 별개의 정확성 판정이다.
2. **오프라인 입력 비교**: A1↔B1·A2↔B2에서 후보 30개(ID·순서·융합 점수)·가사 결과·보호 판정·tier·그룹 구성·그룹 입력 점수·프롬프트 sha·합성값을 질의별로 대조. **A1↔A2·B1↔B2가 입력 필드에서 하나라도 다르면 원인을 먼저 해결**하고 live로 넘어가지 않는다.
3. **최종 품질(live)**: Hit@1/5/10·MRR@10·후보 회수를 176·가사 19·나머지 157로 따로 보고. A/B 차이는 **A1↔A2·B1↔B2 반복 차이(모델 변동 범위)와 함께** 읽는다. A/B 차이가 (a) 두 쌍(A1↔B1, A2↔B2)에서 같은 방향이고 (b) 오프라인에서 그 질의의 후보·보호 그룹·프롬프트가 실제로 달랐을 때만 "구현 차이로 설명됨"이라 부른다. 입력이 같은 질의의 차이는 모델 변동으로 분류한다.
4. 19질의 결과를 일반화하지 않는다. 가중치·필터·프롬프트·후보 수를 결과에 맞춰 바꾸지 않는다. B에서 품질 손실이 보여도 A(고정 상한)를 복원하지 않고 원인만 보고한다. 같은 결과가 나와도 "항상 동일"이라 하지 않는다.
5. 실패(failed·budget_exhausted·partial)는 분모에서 빼지 않고 기본 집계에 남긴다. 장애 진단 재실행은 원본과 분리한다.

1. **정확성 — 수정(B)은 가사 경로가 있는 서비스 조건에서도 독립 합산 기준과 311/311 일치**(오프라인 2 + live 2 실행). 고정 상한(A)은 같은 4건에서 dense 몫을 빠뜨린다. 이 판정은 품질과 무관하게 수정이 맞다는 근거다.
2. **후보·리랭커 입력** — 176질의 중 t003의 점수 1건(Δ0.00022)만 다르고 순서·보호 그룹·프롬프트는 같다. 리랭커에 들어가는 문자열이 A·B에서 같으므로, 이번 자료에서 A/B 품질 차이가 생길 통로가 없었다.
3. **최종 품질** — 네 실행 모두 81 / 107 / 117 · MRR 0.532, 질의별 순위 176/176 동일. A/B 차이 0이 A/A·B/B 반복 차이 0과 같은 크기라 "변화 없음"으로 읽는다. 19질의(12/15/16)는 작은 표본이라 따로 일반화하지 않는다.
4. **재측정 필요 여부** — v61 §8-4 (마)의 조건("가사 경로 있는 조건에서 후보 30개가 같으면 재측정 불필요")을 **후보 ID·순서·모델 입력까지** 충족했다. 지금 dev 176·현재 코퍼스에서 v62 수정 뒤 리랭킹 품질을 다시 잴 이유는 없다. 다만 이것은 이 코퍼스(5,143곡, 상한 5,000의 97.2%)의 결과이고, 코퍼스가 커질수록 고정 상한의 누락은 커진다(v61 §5-4) — 수정을 되돌릴 근거가 아니다.
5. 같은 결과가 나왔다고 "항상 동일"을 주장하지 않는다(§5-2). 가중치·필터·프롬프트·후보 수는 바꾸지 않았다. test는 쓰지 않았다.
