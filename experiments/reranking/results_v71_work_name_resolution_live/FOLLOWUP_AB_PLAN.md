# 후속 리랭킹 A/B 계획(제안 — **실행하지 않음, 승인 필요**)

작성 2026-10-18. 근거는 v71 `RUN_INFO.md` §9다: 후보 단계 근거 있음(두 반복 모두 122→125, 같이 얻은 3, 손실 0), 해석 정확도는 미측정이다.

## 1. 두 가지 평가는 묻는 것이 다르다

| | ① 검색 효과 평가(해석 캐시 고정) | ② 전체 경로 평가(해석 포함) |
|---|---|---|
| 묻는 것 | 실제 해석 출력이 주어졌을 때 보조 후보가 **리랭킹 뒤에도** 남는가 | 서비스로 켰을 때 해석의 변동·실패·시간 초과·대기 지연까지 포함한 결과 |
| B의 해석기 | `cache:resolution_cache/rep1.json`(v71 실제 출력, 두 반복이 같음) — 해석 호출 0 | 운영 `vertex` 해석기 — 실행마다 판정 통과 22질의 실제 호출 |
| 고정되는 것 | 해석 결과(검색·리랭킹 차이만 남음) | 없음(해석 변동이 결과에 섞임) |
| 지연 | 해석 지연이 빠진다(검색 단계 +약 85ms만) | 해석 대기(약 +0.9초 추정)가 들어간다 — 서비스 HTTP 경로(v64 서버 모드)로 재야 의미가 있다 |
| 언제 | 먼저 | ①이 긍정적이고, 활성화를 논의하기 직전에만 |

## 2. ① 검색 효과 평가(권하는 첫 단계)

- 구성: A = 현행(해석 OFF) · B = 현행 + `WORK_NAME_RESOLUTION_ENABLED=1` · `WORK_NAME_RESOLVER=cache:<v71 rep1>`. 그 밖은 v66~v69 서버 기준과 같다(소리 ON · Context 0.5 · D OFF · 피드백 OFF · Gemini listwise · 같은 정책).
- 순서는 동시 대조군 규칙대로 A→B→B→A, 각 176(실패 포함 분모). v69 평가기를 쓴다.
- 비용: 리랭킹 4실행 × 약 $0.77(v69 실측 $0.767/실행) ≈ **$3.07** + 해석 $0. **상한 $5.5 · 750회 · 120분**(v70 §7 그대로 — 실패 예약 미확인 여유 포함).
- 지표: Hit@1/5/10 · MRR(실패 포함 분모) + 질의별 짝 비교 + 리랭커 입력이 바뀐 16질의 따로 집계.
- **효과의 범위**:
  - 리랭커 입력이 바뀌는 질의는 채택 16건이다. 나머지 160건은 후보가 A와 같아 입력이 같다.
  - 새로 후보에 든 정답으로 얻을 수 있는 Hit@10은 최대 3건(후보 13·25·3위)이다. 이것이 전체 개선 상한은 아니다.
    - 16건 안에서는 후보 순서 변화로 기존 후보 안의 실패 질의가 살아날 수 있다.
    - 기존 성공 질의를 잃을 수도 있다.
  - Hit@10의 후보 기준 상한은 B 125/176 = **71.0%**(A 122/176 = 69.3%)다. 도달 가능한 최댓값일 뿐 실제 성능 예상치가 아니다.
- **변동은 이번 평가에서 직접 잰다** — 이전 기록의 실행 간 차이를 고정된 오차 범위로 쓰지 않는다. 그 기록에는 요청 실패와 출력 변동이 섞여 있었다.
  - 같은 입력 반복: A1↔A2, B1↔B2의 질의별 Hit@10 뒤집힘 수와 최종 10위 순서 차이.
  - 같은 입력 대조군: 160건은 네 실행 모두 입력이 같다. 이 160건에서 A와 B 사이에 나는 차이는 모두 변동이다(구성 효과 0).
  - 원인 분리: 실행마다 질의별 리랭킹 상태(`ok` · `model_partial` · `failed` · `budget_exhausted` · `policy_skipped`)를 기록한다. 뒤집힘을 둘로 나눈다.
    - (a) 한쪽이라도 실패·부분 실패·예산 소진(검색 순서 폴백 포함)인 경우.
    - (b) 양쪽 모두 모델 정상인데 출력이 다른 경우.
  - 2회 반복으로 잰 변동은 거친 추정이다. 반복을 늘리면 실행당 약 $0.77이 더 든다. 늘릴지는 실행 전에 정한다.
- 판단 규칙(실행 전 고정할 안):
  - 질의별 분류.
    - "안정 이득": A 두 번 모두 10위 밖, B 두 번 모두 10위 안.
    - "안정 손실": 그 반대.
    - 나머지는 "불안정"이다.
  - 같은 입력 160건에서 안정 이득·손실 꼴이 나온 비율을 변동만으로 생기는 비율로 본다.
  - 이득으로 보려면 세 조건을 모두 만족해야 한다.
    - 16건의 안정 이득이 1건 이상이다.
    - 그 수가 "160건의 변동 비율 × 16"보다 크다.
    - 16건의 안정 손실이 0이다.
  - 주 결과는 실패를 포함한 176 분모다. 보조 결과로 네 실행 모두 리랭킹이 정상인 질의만 본다.
  - 실패 질의를 골라 다시 돌리지 않는다. 정지 등으로 실패가 많아 비교할 수 없으면 판단을 보류로 보고한다.
- 절약안(사용자가 받아들일 때만): B를 16건만 재는 방식이 있다. 이 방식은 동시 대조군 규칙에서 벗어나고, 160건으로 변동을 직접 재는 대조군도 잃는다. 그래서 기본안으로 두지 않는다.

## 3. ② 전체 경로 평가(조건부)

- ①에서 B ≥ A이고, 사람 라벨(v71 `labels/`)로 잘못된 작품 연결의 피해를 본 뒤에만 한다.
- 서버 모드 HTTP(v64 방식)로 A·B를 2회씩 잰다.
- 비용:
  - 리랭킹 약 $3.07.
  - 해석 2실행 × 22회 × 약 $0.0002 ≈ $0.01.
  - 다만 해석 시도도 1회 $0.0988을 예약한다. 리랭킹과 동시에 열리는 예약이 늘어나므로 **상한 $6.0 · 800회 · 150분**을 제안한다.
- 해석 실패·시간 초과는 B 결과에 포함한다(기존 검색 복귀). 해석 대기 지연을 판정 통과 질의와 판정 밖 질의로 나눠 보고한다.

## 4. 이 A/B로 말할 수 없는 것

- 채택 여부. dev 176은 개발 자료다. 채택은 새 `general` 봉인 세트에서만 판단한다(v70 `NEW_DATA_PLAN.md`).
- 해석 정확도. 사람 라벨로만 잰다.
- 작품 지칭 질의가 실제 사용자 분포에서 얼마나 흔한지.
