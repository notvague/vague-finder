# 작품 라벨 대기표 — 사람이 채운다(v71)

대기표 `work_label_queue.csv`(질의 id만, Git 추적)와 `work_label_queue_private.csv`(질의 원문 포함, Git 제외)를 2026-10-18 13:09 KST, **실제 해석 호출 전에** 만들었다. 대상은 v70 판정(`gate_v2`)을 통과한 dev 22질의다.

## 누가

- **라벨러**: 드라마·예능·영화를 잘 아는 팀원 1명(+ 가능하면 두 번째 확인자 1명). PM이 정한다.
- 라벨러는 **모델 출력(`live/`·`resolution_cache/`·RUN_INFO §6의 작품 후보)을 보기 전에** 채운다. 이미 봤으면 `saw_model_output_before=yes`로 적는다. 그 행은 독립 라벨로 세지 않는다.
- 정답 곡을 이미 아는 사람(질의 작성자 등)이면 `saw_answer_song_before=yes`로 적는다. 이것 때문에 행을 빼지는 않는다. 다만 정답 곡과 관계없이 "질의 문장이 가리키는 작품"을 적는다.
- 에이전트는 이 표를 채우지 않는다. 에이전트나 모델이 붙인 라벨은 정답 판정으로 쓰지 않는다.

## 무엇을

| 열 | 값 |
|---|---|
| `intended_work` | 질의 문장만 읽고 사용자가 가리킨다고 판단한 작품명. 모르면 비운다 |
| `alternative_works` | 같은 설명에 맞는 다른 작품(`;`로 구분) |
| `multiple_possible` | yes · no · unsure — 설명이 여러 작품에 맞는가 |
| `undeterminable` | yes · no — 설명만으로 작품을 정할 수 없는가 |
| `evidence` | 판단 근거(질의의 어느 구절이 그 작품을 가리키는가, 외부 확인 출처) |
| `labeler_id` · `labeled_at` | 이니셜·날짜 |
| `saw_model_output_before` · `saw_answer_song_before` | yes · no |
| `notes` | 그 밖의 메모 |

- **정답 곡이 그 작품에 쓰였다는 이유만으로 그 작품을 사용자가 뜻했다고 단정하지 않는다.** 질의 설명과 작품이 맞는지를 본다.
- `v67_known_case=yes`는 v67 진단의 간접 지칭 묶음 사례(10건)라는 표시다. 나머지 12건이 오답이나 음성 사례라는 뜻은 아니다.
- `v67_prior_label=v67_answer_derived`: v67 `oracle_work_name.py`에 작품명이 있는 질의다. 그 목록은 정답 곡 자료(진단표 근거 열)를 보며 적었다(작성 주체 기록은 "사람이 정한"이지만 에이전트 세션의 코드 파일이다). 그래서 **의도 라벨로 재사용하지 않고** 출처만 표시한다. 라벨러에게는 그 이름을 보여 주지 않는다.

## 채운 뒤

에이전트가 라벨과 `live/rep*/` 출력을 대조해 정답·오답·보류율을 낸다. 규칙은 RUN_INFO §8에 실행 전 고정했다.
