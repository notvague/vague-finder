**깊이 제한을 풀고 속성 가산(시기·성별·장르·형태)을 더하면 30위 안**이었다(n002 1위 · t011 2위 · q112 4위 …). 경로 깊이를

현행과 비트 단위로 같다. 봉인 test(v10 42건)는 열지 않았다.

## 1. 경로가 하는 일

1. `_build_attribute_filter(analysis)` — 분석에서 payload 필터를 만든다. 뜻은 기존 가산 규칙과 같게 맞췄다
   - 시기: `release_era` 창 안의 연도마다 `release_date $text "YYYY"`(발매일이 문자열이라 범위 대신 전문 일치; 창이 13년 이상이면 조건에서 뺀다)
   - 성별: 남성/여성은 `혼성`도 허용(`vocal_gender_partial`과 같음), 혼성은 그대로
   - 장르: 분석의 말("록")이 등록 장르 표기("록/메탈")의 부분 문자열이면 그 표기들 `$in`(`genre_match`와 같은 규칙, 등록 장르에 없는 "펑크록"은 조건이 안 된다)
   - 형태: `canonical_artist_types` 별칭을 거꾸로(밴드 → 밴드·인디밴드 …)
2. 여는 조건 `ATTR_FILTER_GATE`: `two_axes`(기본 — 시기 창이 있거나 다른 축 둘 이상) · `era_plus`(시기 창 **그리고** 다른 축 하나 이상)
3. 열리면 `_search_text`를 같은 dense/sparse 질의 + 이 필터로 한 번 더 부른다(`ATTR_FILTER_K`개, 기본 30). 결과는 `performance_metadata` 경로와 같은 자리에서 `가중 / (RRF_K + 순위)`로 융합 점수에 더한다(가중 `ATTR_FILTER_WEIGHT`, 이번 실험 0.5). 기존 후보를 빼는 hard filter가 아니고, 순위는 아래 속성 가산이 다시 정한다(이 목록의 곡은 조건에 맞으니 그 가산을 받는다)
4. 기록: explain 경로 `attr_filter`("속성 조건 보조"), runinfo `ranking_switches.attr_filter_{weight,k,gate}`

로컬 Qdrant에서 필터 검색 한 번은 검색(후보까지) 중앙값을 0.55초 → 0.78초로 늘린다(+0.23초, p95 +0.56초). 서버 모드·payload 색인에서는 다를 수 있다.
