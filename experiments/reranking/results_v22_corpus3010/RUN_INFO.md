## 관찰 1 — 정답이 최종 후보 밖으로 빠진 질의가 늘었다

dev에서 새로 빠진 질의는 9건이다: c603 · c701 · m302 · q110 · q112 · q115 · q203 · q208 · q210.
test는 v21과 같은 5건이다.

q110·q112는 v21에서 1위였다.

| | v21 기록 | v22 기록 |
|---|---|---|
| q110 | 텍스트 경로 8위 · 제목 의미 경로 1위 · 편성 경로 14위, 성별·제목 의미·그룹 형태 가산 | 최종 후보 30 밖 |

**어느 단계에서 빠졌는지는 확인하지 못했다.** 저장된 기록은 "정답이 후보 풀에 없음"까지만
남기므로, 경로 회수·RRF 융합·가산 후 절단 중 어디서 사라졌는지 구분할 수 없다.
후보 폭이 원인이라는 것은 실험으로 확인할 **가설**이다.

실험할 때 주의: 지금 `candidate_k`는 각 경로가 가져오는 깊이와 최종 후보 수를 함께 정한다
(`src/retrieval/search_router.py` `candidates`·`pool_k`). 값만 올리면 최종 후보 수와 검색 점수
정규화 범위까지 바뀌어, v21에서 문제가 됐던 정규화 효과가 섞인다.

## 허용 정답을 넣은 확장 지표 (v07 라벨) · 2026-10-01

모호한 질의 72건의 후보(v21·v22 top-10 합집합 + 원래 타깃, 1,198행)를 팀이 조건별로 판정했다.
원래 타깃(`positives`)은 그대로 두고, 질의 설명에 맞는 다른 곡을 허용 정답(`allowed`)으로 더했다.

- 라벨: `docs/eval/queries.json` 0.5.2의 `allowed` — 질의 20개(dev 15 · test 5)에 80곡.
  측정용 CSV는 `python -m src.eval.export_csv --with-allowed --out experiments/reranking/eval_queries_v07.csv`로 만든다.
  `eval_queries_v06.csv`는 원래 타깃만 담은 기준 세트로 그대로 둔다
- 집계: `python -m src.eval.relaxed_metrics --result-dir <결과 폴더>` — 검색을 다시 돌리지 않고 detail의 top-10으로 계산한다.
  엄격 지표는 원래 타깃만, 확장 지표는 원래 타깃 + 허용 정답을 정답으로 센다. 엄격 지표는 원래 요약과 일치함을 확인했다
- 판정 근거: 가사 원문, 멜론 메타데이터, 수집 원문(앨범 소개·댓글·나무위키), 표지, 웹 출처(기사·위키백과),
  팀 결정, 청취 확인. 생성 태그·생성 요약·모델 지식만으로 정한 칸은 승인에도 기각에도 쓰지 않았다
  (검색과 평가가 같은 생성 오류를 공유하지 않게). 검토표와 근거는 곡 목록 공개 방침에 따라 레포 밖에 둔다

**읽는 법**

- v21과의 차이가 줄었다. dev Hit@10 차이는 9건(45 vs 36) → 4건(48 vs 44), MRR@10 차이는 0.087 → 0.037.
  dev Hit@1은 확장 지표에서 v22가 앞선다(28 vs 26). 3,010곡에서 떨어진 몫의 일부는 "질의에 맞는 새 곡이
  라벨에 없어서"였다
- 그래도 다 설명되지는 않는다. dev Hit@10은 여전히 4건 적고, test Hit@1은 차이가 그대로다(16 vs 12).
  관찰 1의 후보 탈락(q110·q112·q208·q210 등, 정답이 분명한 질의)은 라벨과 무관한 실제 손실이다
- v22에서 허용 정답이 원래 타깃보다 먼저 나온 질의: dev q115 · q117 · m104 · m201 · m202 · m302 · m303 · m402 ·
  m403 · c601 · c603 · c605, test q116 · m301 · m401 · c608

**한계**

- 허용 정답은 v21·v22 top-10에 든 후보만 검토했다. 다른 설정의 측정에 쓰면 검토하지 않은 곡이 top-10에
  들어와도 오답으로 세므로 확장 지표가 낮게 나올 수 있다. 새 설정을 비교할 때는 새로 들어온 후보를 검토해야 한다
- 판정하지 못한 후보 1곡(검색이 원래 타깃보다 위에 올린 곡)은 오답으로 셌다
- 방송 삽입·챌린지 역주행 같은 '유명 사건' 조건은 웹에서 기사를 찾지 못하면 불충족으로 판정했다. 원래 타깃의
  사실도 웹 검색에 안 잡힌 경우가 있어, 이 규칙은 허용 정답을 적게 셀 수 있다
- 원래 타깃 3곡은 질의 조건과 사실이 달라 검토에서 부적합으로 나왔지만(질의 작성자의 기억 차이), 정답으로 남겼다
- Recall@10·nDCG@10은 확장 지표로 내지 않는다. 허용 정답 수가 질의마다 달라 분모가 흔들린다.
  Candidate Recall@30은 후보 30개 목록이 detail에 없어 재실행이 필요하다
- test 25건은 여러 번 쓴 분할이다
