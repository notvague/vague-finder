# 등록 장르와 사용자가 기억하는 장르·가수 정체성의 간격 — 진단과 장르 가산 실험 (results_v01, 2026-10-13)

사용자가 말하는 '발라드'는 체감 스타일일 수 있고 '인디'·'아이돌'은 가수의 활동 배경일 수 있다. 멜론 등록 장르와 다른 말로 기억해도
곡을 찾는지, 못 찾는다면 **어느 단계에서** 잃는지 봤다. 장르 가산만 떼어 낸 실험 배율 둘을 더했고(기본값은 그대로), 기본값을
바꿀지는 아래 채택 기준으로 판단했다. **봉인 test는 열지 않았다. 서비스 기본 동작은 바뀌지 않는다.**

## 결론

1. **체감 장르로 말하면 실제로 덜 찾는다. 잃는 곳은 리랭커가 아니라 후보 생성이다.** 간격 사례 15곡을 같은 문장에서 장르 낱말만 바꿔
   물으면 후보 30 안에 드는 곡이 등록 장르 표현 11 · 장르 낱말 없음 11 · **체감 장르 표현 6**이다. 리랭커는 후보에 든 정답을 전부 10위
   안으로 올렸다(§2)
2. **장르 낱말은 두 군데서 작용한다.** 명시 가산(`genre_match`)이 등록 장르가 맞는 다른 곡을 올리고, 그보다 먼저 텍스트 검색(주
   텍스트 경로와, 같은 검색문·태그를 쓰는 보조 검색)에서 질의문·태그의 장르 낱말이 등록 장르가 그 낱말인 곡을 끌어온다. 가산을 끄면
   6 → 8곡이고, 남은 3곡은 텍스트 검색에서 잃는다 — 주 경로 상위 30이 아니라 보조 신호로 들던 곡들이 그 신호가 읽는 깊이 밖으로
   밀린다(§2 ③). 4곡은 장르 낱말만 바꾼 세 문장 어느 것으로도 못 찾는다 — 장르 표현과 무관한 검색 실패다(그중 강남스타일은
   정체성·소리 문장으로는 찾는다)
3. **사용자가 장르를 말하지 않아도 같은 일이 생긴다.** 모델이 원문에 없는 장르를 짐작해 채운다(장르 낱말이 없는 문장 40건 중 11건).
   기존 dev 176건에서도 장르가 든 분석 76건 중 26건은 정답의 등록 장르와 맞지 않는다
4. **장르 일치 가산을 끄면(`GENRE_MATCH_SCALE=0`) — 리랭커 켬, 2회 모두 같은 값**: 새 세트의 체감 장르 문장 Hit@10 6 → 8(예뻤어 · 무제),
   등록 장르 문장은 그대로, 기존 dev 176은 Hit@10 113 → 114 · Hit@1 72 → 77 · MRR 0.492 → 0.512. 10위 밖으로 빠진 것은 1건이다
   (n082 — 드문 장르를 맞게 말한 질의). 중간값 0.5 · 0.25는 후보 단계에서 거의 켠 것과 같았다(§3)
5. **기본값은 바꾸지 않았다.** `GENRE_MATCH_SCALE=0`은 계획서가 정한 "기본값 변경 후보" 조건 가운데 검색 품질 쪽을 넘겼다. 재질문
   2턴에서 회귀가 없는지는 **재지 못했다** — 측정 도중 AI Studio 선불 크레딧이 떨어졌다(§4-2). 채택은 그 측정과 Context 적용 뒤
   재검증, 최종 설정 결정에 맡긴다(§7)
6. **재질문 장르 답변 가산(`GENRE_ANSWER_SCALE`)은 1.0을 유지한다.** 후보 단계에서 맞는 답에는 이득이고 체감 장르로 답하면 손해인데,
   줄여도(0.5) 어느 쪽도 바뀌지 않고 끄면 둘이 함께 사라진다(§4). 리랭커를 켠 비교는 기준선 1회뿐이다
7. **'아이돌' 같은 가수 정체성은 곡 정보에 닿을 자리가 없다.** 원인으로 확인했지만 보강 실험은 하지 않았다 — 일부 가수에만 붙이면
   정답을 알려 주는 셈이라 공정하게 잴 수 없다(§5)

- **장르 낱말은 가산보다 먼저 텍스트 검색에서 작용한다.** 질의문(dense)과 태그(BM25)에 장르 낱말이 그대로 들어가고 곡 passage에는
  "장르: 발라드"가 들어 있다. 같은 문장에서 장르 낱말만 등록 → 체감으로 바꾸면 **주 텍스트 경로 순위가 15곡 중 10곡에서 나빠진다**
  (봄날 31 → 172 · STAY 42 → 410 · 예뻤어 7 → 55 · 무제 26 → 51 …, 나아진 곡 1 · 같은 곡 4). 같은 검색문·태그를 쓰는 보컬·편성 전용
  검색에서도 두 문장 모두 순위가 있는 14곡 중 11곡이 나빠진다(TOMBOY 3 → 47 · STAY 12 → 145 · 봄날 25 → 189 …, 나아진 곡 1 · 같은 곡 2)
- **모든 곡에서 그런 것은 아니다.** 대조군 거리에서는 등록 장르를 맞게 말한 g16r가 경로 밖이고(텍스트 244위), 장르 낱말을 뺀 g16o가
  텍스트 41위 · `metadata` 3위로 들어 후보 14위 · 최종 1위다. 장르 낱말을 맞게 말한 쪽이 더 멀어진 사례다

  가산(+1/61)을 받아 정답을 넘었다. 가산을 낮추면 후보에 든다(§3)

## 3. 장르 일치 가산 배율 — `GENRE_MATCH_SCALE` (B)

`search_router._genre_match_scale()` — `_apply_explicit_boosts`의 `genre_match` 한 줄에만 곱한다. 기본 1.0(현행), 범위 0~1,
0이면 가산도 기록도 없다. 숫자가 아니거나 NaN·inf면 기본값, 음수는 0, 1보다 크면 1로 읽는다. runinfo `ranking_switches.genre_match_scale`에
실제 적용값이 남는다. `ATTR_BOOST_SCALE`과 달리 성별·시기·형태·편성 가산은 건드리지 않는다.

**이번에 바꾸지 않은 장르의 영향** — 0이어도 "장르의 영향을 모두 없앤" 실행이 아니다.
- 질의문(dense)과 태그(BM25)에 든 장르 낱말, 곡 passage에 든 등록 장르 문자열 — 주 텍스트 경로와 보조 검색 모두에 들어간다.
  §2 ② · ③에서 본 대로 이쪽이 더 크다
- 가사 exact 후보를 묶는 보조 점수(`exact_lyric_constraint_score`의 장르 +1.0)
- 보조 경로의 BM25 질의에 들어가는 `analysis.genre`(`_search_performance_clues` · `_search_title_meaning`) · 공연 단서 필터의 `랩/힙합`
  — `genre` 칸을 비워 봐도 새 세트에서 후보에 드는 곡은 그대로였다(§2 ③)
- 리랭커 프롬프트의 후보 `genre` 칸 · 재질문 장르 답변 가산(§4) · 가사 exact 묶음이 답을 읽는 방식

## 4. 재질문 장르 답변 가산 — `GENRE_ANSWER_SCALE` (B-4)

`search_router._genre_answer_scale()` — 재질문의 **장르 답변** 가산(답변 배수 ×3, `clarify.apply_answer_bonus`)에만 곱한다. 기본 1.0,
범위·읽는 규칙은 위와 같다. 성별 답변의 가산, 일치 판정(`answer_matches`), 거절 곡 제외, 리랭커에 넘기는 답변은 바꾸지 않는다.
`GENRE_MATCH_SCALE`과 서로 영향을 주지 않는다(시험으로 확인).

재질문은 "어떤 장르에 가까웠나요?"라고 묻지만 선택지는 후보의 첫 등록 장르고 일치도 등록 장르로 판정한다. 체감 장르로 답한
사용자의 정답은 가산을 못 받고, 그 답으로 등록된 다른 곡이 ×3 가산을 받는다.

### 4-1. 후보 단계 — 1 / 0.5 / 0 (리랭킹 없음, `diagnose_genre_gap answers`)

정답이 후보 순서의 10위 밖인 질의에서 앞 10곡을 거절한 뒤 장르를 답했을 때 정답의 후보 순위. 리랭커가 없으므로 "보여 준 10곡"은
후보 순서의 앞 10곡이다(서비스는 리랭킹한 10곡을 보여 준다).

|---|---|---|---|---|---|---|
| 기존 dev 176 | 거절만 | – | 78 | 24 | 15 | 3 |

| | | 0.5 | | 24 | 18 | 8 |
| | | 0 | | 24 | 15 | 3 |
| 새 세트 79건 | 거절만 | – | 32 | 7 | 2 | |

| | | 0 | | 7 | 2 | |
| | 체감 장르 답 | 1 · 0.5 | 28 | 6 | **0** | |

- **답변은 후보 집합을 바꾸지 않는다.** 가산은 절단 뒤에 붙으므로, 체감 장르로 답해도 정답이 후보에서 사라지지는 않는다. 다만 후보
  끝으로 밀린다 — 예뻤어 g04i 5위 → 21위, 눈, 코, 입 g07o 23 → 30위, 무제 g08i 18 → 26위(거절만 했을 때 → 체감 장르 답)

- **중간값은 어느 쪽도 바꾸지 못한다.** 0.5에서 맞는 답의 이득은 거의 그대로고(18 · 8) 체감 장르 답의 손해도 그대로다(0).
  0으로 끄면 둘이 함께 사라져 거절만 한 것과 같아진다
- 서비스가 실제로 장르를 묻는 것은 개입 질의 중 일부다 — 질의가 장르를 이미 말했으면 묻지 않고(#40), 성별이 먼저다.

## 6. 피드백 후보 보충 · 설명

- **닿는 경로는 하나다.** 보충 곡의 진입은 "밀려날 꼬리 후보의 융합 점수 × 가중 + 명시 단서 보정"이 절단을 넘는지로 정하고, 그
  보정이 `_apply_explicit_boosts`(장르 가산 포함)다. 보충이 없을 때의 기준 후보와 실제 후보를 **같은 배율로** 계산한다
- 계약 시험(`tests/test_genre_match_scale.py`): 후보가 모두 말한 장르로 등록돼 있으면 등록 장르가 다른 보충 곡은 현행에서 못
  들어오고 배율 0에서 들어온다. 어느 배율에서도 들어온 곡은 후보 끝에 서고, 나머지 후보의 점수·순서와 리랭커 없이 나가는 표시
  결과는 보충이 없을 때와 같다
- 합성 비교(`evaluate_feedback_reuse compare --synthetic`)는 배율 1과 0에서 결과가 같다 — 둘 다 보충 적용 5 · 진입 8 · 후보 Recall
  0.4 → 0.8. 합성 분석에 장르가 없어서다. **보충이 0건은 아니지만 장르 배율에 민감한 측정이 아니므로 검증으로 세지 않는다.**
  실제 코퍼스에서 피드백을 켠 측정은 하지 않았다(승인 사례가 없다)
- 설명: 사용자용 근거의 장르 줄은 "등록 장르가 맞는다"(사실)를 곡 정보에서 읽고, "검색 점수에 반영"은 가산 기록이 있을 때만 쓴다.
  배율 0.5면 기록된 값(= 실제로 더한 값)이 그대로 연결되고, 0이면 `일치` + `순위 반영 기록 없음`이다. 실제 `search()` 흐름에서
  경로 기여 + 가감점 = 검색 점수가 맞는지도 시험에 넣었다

## 7. 채택 판단

계획서 §8의 "기본값 변경 후보 조건"에 비춰 본 `GENRE_MATCH_SCALE=0`:

| 조건 | 결과 |
|---|---|
| 체감 장르 변형에서 서로 다른 정답 곡 2개 이상 회복, 두 실행에서 재현 | **충족** — 예뻤어 · 무제, 2회 모두 |
| 등록 장르 대조군의 Hit@10 · MRR이 두 실행 모두 나빠지지 않음 | **충족** — 20건 Hit@10 15 → 15 · MRR 그대로 |
| 기존 dev의 Hit@10 · MRR이 두 실행 모두 나빠지지 않음 | **합계는 충족**(113 → 114 · 0.492 → 0.512). 세트로 나누면 v09 Hit@10이 38 → 37이다(n082) |
| 재질문 · 거절 계약 회귀 없음 | 계약 시험은 통과(왕복 · 건너뛰기 · 거절 · 성별 답 불변). **하네스 측정은 못 함**(§4-2) |
| 기준선 반복 변동과 겹치지 않음 | **충족** — 같은 설정 2회에서 정답 곡의 최종 순위가 255건 모두 같았다(상위 10곡 목록은 기준선 2회 사이에 2건 다름) |

**판정 — 기본값 1.0 유지.** `GENRE_MATCH_SCALE=0`은 위 표의 검색 품질 조건을 넘겼지만, **재질문 2턴에서 회귀가 없는지는 재지 못했다**
(AI Studio 크레딧 소진, §4-2). 그래서 "후보 조건을 모두 넘겼다"고 적지 않는다. 남은 확인은 셋이다 — ① 크레딧을 채운 뒤 재질문 하네스
(0, 1) 2회와 기준선 재측정 ② Context를 올린 색인에서 같은 비교 ③ 그 뒤 최종 설정 결정. 계획서도 조건을 넘긴 뒤에 Context 재검증을
거쳐 채택하라고 했으므로, 재질문 측정이 됐더라도 이 변경에서 기본값은 바꾸지 않았을 것이다.

함께 적어 둘 것 — 가산을 끄면 잃는 쪽도 있다. 드문 장르를 맞게 말한 질의(n082 '록' · n018 '트로트')는 가산이 정답을 받쳐 주고 있었다.
흔한 장르(발라드 · 댄스)에서는 가산이 경쟁곡을 올리는 쪽이 크다. 장르마다 다르게 다루는 안은 재지 않았다.

`GENRE_ANSWER_SCALE`: **후보 아님, 1.0 유지.** 후보 단계에서 얻는 것(체감 장르 답의 손해 제거)과 잃는 것(맞는 답의 이득)이 함께
묶여 있고 중간값은 효과가 없다(§4-1). 리랭커를 켠 비교는 하지 못했다.

가수 정체성 보강(C): **하지 않음.** 필요한 자료와 평가 방법만 §5에 적었다.

## 8. 재지 않은 것 · 한계

- **Context 색인이 없는 색인으로 쟀다.** #45의 5곡 수정 전 색인이기도 하다. Context 적용 뒤에 같은 비교를 다시 해야 한다 — 그 값은
  이 문서에 없다
- 새 비교 질의는 작성자 초안이다(사람 검토 전). 체감 장르는 작성자의 판단이고 20곡뿐이다. 통계적 일반화가 아니다
- 세 문장(등록 · 체감 · 없음)은 장르 낱말만 다르지만 분석은 문장마다 따로 한 번 했다. 장르 칸 밖의 분석 차이가 섞여 있고, 분석의
  반복 변동은 재지 않았다
- 넓은 질의의 조건 적합성은 후보 순서 기준이다(리랭커 미측정). '아이돌' · '잔잔한' · '인디 느낌'은 판정하지 않았다
- 확장 지표(허용 정답)를 계산하지 않았다 — 새로 10위 안에 든 곡을 판정하지 않았다. 다른 판(g12 · g18)도 정답으로 세지 않았다
- 지연은 비교하지 않았다(병렬 실행). 봉인 test는 열지 않았다
- 피드백을 켠 실측은 하지 않았다(§6). 실제 서버·브라우저로는 돌려 보지 않았다
- 장르의 다른 영향(§3의 목록)은 고정했다. 특히 텍스트 검색(주 경로와 보조 검색)에 들어가는 질의문·태그의 장르 낱말은 이번에
  건드리지 않았고, 체감 장르 문장에서 잃는 곡의 더 큰 몫이 거기에 있다
- 장르 가산을 0.5 · 0.25로 둔 리랭커 측정은 하지 않았다(후보 단계만)
- **재질문 2턴 하네스는 기준선 1회만 유효하다**(§4-2) — 두 배율을 바꾼 재질문 결과가 없다

로컬 Qdrant는 한 프로세스만 연다. 나란히 돌리려면 색인 복사본을 따로 두고 `QDRANT_PATH`를 달리 준다(세 개를 동시에 올렸을 때 한 번
프로세스가 죽었다 — 그 실행은 다시 쟀다).

**후보 단계 산출물은 다시 돌려도 같다.** 리뷰 1회차 뒤 도구에 열(`target_paths` · `performance_search_rank` · `blanked_genre`)을 더하고
추적 · 경로 깊이 · 답변 후보 단계 · 집계(`trace_*` · `depth*` · `answers_*` · `report_*`)를 지금 도구로 전부 다시 만들었다. 이전
산출물과 공통 열의 값이 모두 같았다(달라진 것은 기존 dev 세트의 `group` 표기 `all` → 세트 이름, 대조 문장 두 건의 `stated_genre` 표기뿐).
리랭커를 켠 측정(`rerank_*` · `clarify_*`)은 다시 돌리지 않았다 — 서비스 코드는 그 측정 뒤로 바뀌지 않았다.

**집계 도구 수정(10/14).** 측정 수치는 바뀌지 않았다 — 저장된 실행은 재는 조건이 모두 같다.
- 외부 리뷰 2건: ① `report`가 순위가 적혀 있기만 하면 Hit@10으로 세던 것을 1~10위로 고쳤다(MRR@10 · 든 것/빠진 것 목록도 같다)
  ② `summarize_clarify.py`가 실패한 실행을 공통 개입 대상 표에 표시 없이 넣고 공통 대상 계산에도 쓰던 것을 고쳤다
- 리뷰 회차 4의 같은 종류 3건: ③ 두 도구 모두 **재는 조건이 다른 실행을 표시 없이 나란히 놓지 않는다** — 표의 이름이 뜻을 잃는
  경우(후보 깊이 · 보여 준 곡 수가 다름)는 받지 않고, 그 밖의 조건은 runinfo를 기준 실행과 통째로 견줘 다른 칸을 적는다
  ④ 리랭커 상태를 모르는 실행(집계 없음)과 이름을 모르는 실패를 정상으로 치지 않는다 ⑤ 재질문 비교의 규칙(공통 대상은 교집합 ·
  개입 대상은 `reject_only`가 돈 질의 · 질의 안에서 먼저 평균)을 시험으로 고정했다
- 리뷰 회차 5: ⑥ 색인 폴더가 다른 실행이 "다른 조건: 없음"으로 나오던 것을 고쳤다 — 색인 폴더(`corpus.qdrant_path`)를 조건으로 본다.
  **Context를 올린 색인에서 다시 잴 때, 새 색인의 실행을 여기 저장된 기준선과 견주면 그 칸이 다르다고 나온다**(기준선도 새 색인에서 다시 잰다)
- 고친 도구로 `report_*`를 다시 만들었다. `rerank_ranks.csv`는 바이트까지 같고, `rerank_summary.csv`는 기존 열의 값이 모두 같으며 열 다섯
  (`top_k` · `candidate_k` · `path_k` · `analysis_cache` · `conditions_vs_base`)이 늘었다. `summarize_clarify.py`의 산출물은 아직 없다
  (유효한 재질문 실행이 하나뿐이다)
