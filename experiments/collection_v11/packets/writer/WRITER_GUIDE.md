# 노래 검색 문장 쓰기 — 작성자 안내

제목도 가수도 생각나지 않는 노래를 사람들이 어떻게 찾는지 모으고 있습니다. 모은 문장으로 졸업 프로젝트(흐릿한 기억으로 노래 찾기)의 검색 품질을 잽니다. 시간은 문장 하나에 몇 분이면 됩니다.

시작하기 전에 `CONSENT_PRIVACY.md`를 읽고 `declaration_<코드>.csv` 한 줄을 채워 주세요.

## 받은 파일

| 파일 | 하는 일 |
|---|---|
| `writer_sheet_<코드>_<번호>.csv` | 검색 문장을 쓰는 표. 번호(`entry_id`)·코드·`track`은 미리 채워져 있습니다. 고치지 마세요 |
| `declaration_<코드>.csv` | 동의와 자기 보고 한 줄 |
| 이 안내 · `CONSENT_PRIVACY.md` | 읽기만 |

엑셀이나 구글 시트로 열어도 됩니다. 저장은 CSV(UTF-8)로 해 주세요.

## 가장 중요한 것 넷

1. **기억으로 먼저 쓰고, 정답은 나중에 찾습니다.** 노래를 검색하거나 가사·영상을 찾아본 다음에 쓰지 않습니다. 찾아본 뒤에는 이미 쓴 문장을 고치지 않습니다.
2. **우리 검색 서비스에 넣어 보지 않습니다.** 결과를 보면 맞히는 쪽으로 표현을 고치게 됩니다. 이미 넣어 봤다면 `used_system_before`에 `yes`라고 적어 주세요. 숨길 필요는 없습니다.
3. **AI(챗봇 등)로 문장을 만들거나 다듬지 않습니다.** 썼다면 `ai_used`에 그대로 적어 주세요. 그런 문장은 따로 셉니다.
4. **제목과 가수 이름은 쓰지 않습니다.** "제목이 영어 한 단어였다"처럼 모양만 기억나는 것은 써도 됩니다.

## 무엇을 쓰나

- 실제로 떠올린 노래를 떠올린 그대로 씁니다. 친구에게 "그 노래 있잖아…" 하고 묻듯이 쓰면 됩니다. 길이·말투·맞춤법은 평소대로 쓰세요.
- 어떤 노래든 됩니다. 시대·장르·나라를 가리지 않습니다. 우리 노래 목록에 있을지 따지지 않습니다. 목록은 일부러 보여 드리지 않습니다.
- 어떤 종류의 단서를 쓰라는 할당은 없습니다. 기억나는 것만 쓰세요. 단서가 적어도 괜찮습니다.
- 잘못 기억했을지도 모르는 단서도 기억대로 씁니다. 다만 일부러 틀리게 쓰지는 않습니다.
- 한 문장에 노래 하나를 떠올립니다. 같은 노래를 다른 말로 여러 번 쓰지 않습니다.
- 예시 문장은 일부러 넣지 않았습니다. 예시가 있으면 모두 비슷하게 쓰게 됩니다.

### 하지 않을 것

- 이 프로젝트의 저장소(GitHub)·평가 폴더·실험 결과·발표 자료를 보고 쓰기. 이미 봤다면 자기 보고 표에 적어 주세요.
- 개발팀에게 "요즘 어떤 질문이 잘 안 되느냐"고 묻기.
- 다른 작성자의 문장을 보고 쓰기.
- 친구 이름, 학교·회사, 연락처처럼 사람을 알아볼 수 있는 정보를 문장에 넣기.

## 표 채우는 순서

**① 문장을 쓸 때**
- `written_at`: 쓴 시각, `2026-10-21 14:05` 꼴(한국 시각)
- `query`: 검색 문장

**② 쓴 직후(아직 정답을 찾아보지 않은 상태)**

| 열 | 적는 값 |
|---|---|
| `memory_source` | `own_memory`(내 기억) · `helped_recall`(내 기억인데 누가 같이 떠올려 줌) |
| `ai_used` | `no` · `edited`(AI로 다듬음) · `generated`(AI가 씀) |
| `written_before_lookup` | 정답을 찾아보기 전에 썼으면 `yes` |
| `used_system_before` | 우리 서비스에 넣어 봤으면 `yes`, 아니면 `no` |
| `title_recall` | 쓰던 때 제목을: `exact`(정확히 앎) · `partial`(일부만) · `none`(모름) |
| `artist_recall` | 가수를: `exact` · `partial` · `none` |
| `remembered_aspects` | 기억나는 것을 `;`로 여럿: `lyrics`(가사) `melody`(멜로디) `voice`(목소리) `instrument_sound`(악기·소리) `cover`(앨범 표지) `mv`(뮤직비디오) `work`(드라마·영화·예능 등) `place_situation`(들은 곳·상황) `era`(시기) `performer_type`(가수 성별·그룹 등) `title_shape`(제목 모양) `other` `unsure` |
| `work_reference` | 드라마·영화·예능·광고 같은 작품을 떠올리며 썼으면 `yes`, 아니면 `no`, 모르면 `unsure` |
| `work_name_after_writing` | `yes`일 때 떠올린 작품 이름. **문장에는 넣지 않고 여기에만** 적습니다 |
| `work_media_type` | `drama` `film` `variety` `audition` `animation` `webtoon` `musical` `documentary` `game` `ad` `other` |
| `writer_confidence` | 떠올린 노래가 맞다는 확신: `high` · `medium` · `low` |

**③ 이번 표의 문장을 다 쓴 뒤**
- `writer_answer_title` · `writer_answer_artist`: 생각하는 노래. 이때는 찾아봐도 됩니다. 끝내 모르면 비워 둡니다. 모르는 문장도 지우지 말고 그대로 내 주세요.
- `writer_answer_other`: 제목은 모르지만 노래를 알아볼 단서(유튜브 주소 등)
- `answer_noted_at`: ③을 적은 시각

**대화(2턴)는 있을 때만**: 누가 되물어서("남자 가수야?") 답한 적이 실제로 있으면, 첫 문장과 답을 각각 한 줄로 씁니다. `conversation_id`(예: `c1`)를 같게, `turn_no`는 1·2, 두 번째 줄의 `prior_question`에 받은 질문을 적습니다. 실제로 주고받았으면 `turn_origin`=`real_exchange`, 나중에 지어낸 대화면 `constructed`입니다.

## 내기와 고치기

- 표를 다 채우면 받은 경로로 보관자에게 보냅니다. 보관자가 형식만 되물을 수 있습니다(내용 힌트는 주지 않습니다).
- 낸 뒤에 문장을 고치고 싶으면 보관자에게 알려 주세요. 원래 문장은 지우지 않고 새 판으로 남깁니다. 고친 문장은 `edit_confirmed_by_writer`=`yes`, `edit_note`에 고친 이유를 적습니다.
- 한 묶음은 10~25문장이면 충분합니다. 묶음 크기와 횟수는 보관자가 정합니다. 이미 낸 문장을 비율 때문에 버리는 일은 없습니다.
