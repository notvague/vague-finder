# v11 독립 평가 자료 수집 — 준비물

**일정 보류(2026-10-20, 사용자 결정): 포스터 작성을 우선한다. 실제 자료 수집·정답 확인·분할·봉인 및 새 자료를 이용한 검색 평가는 포스터 작업 완료 후 재개한다. 현재 PR은 준비물 보존용이며 수집 시작이나 평가 실행을 승인하지 않는다.**

작성 2026-10-20. 이 폴더는 개발 실험과 따로 운영하는 **자료 수집**용이다. 목적은 두 가지다. 실제 기억으로 쓴 검색 질의를 모으고, 개발 자료(`policy_dev`)와 봉인 평가 자료(`sealed_eval`)를 결과를 보기 전에 갈라 둔다. 특정 개선안(소리 경로 생략·작품명 해석·v76/v77 앨범 소개 보조)에 유리한 질의를 모으려는 것이 아니다.

## 0. 상태 — 네 단계를 따로 적는다

| 단계 | 상태(2026-10-20) |
|---|---|
| 준비(양식·안내·검사 도구·전달 패킷) | **완료.** 합성 자료 자체 검사 통과(`SELFTEST.md`) |
| 실제 수집 | **0건.** 시범 작성자 3명 × 10건으로 결정(2026-10-20), 작성자 미지정 · 연락 안 함 |
| 정답 확인 | **0건.** 확인자 미지정 |
| 분할·봉인 | **안 함.** 보관자 지정(2026-10-20, 이름은 보관자 대응표에만) · 보관자 폴더·salt 아직 없음 |

현재 숫자는 `COLLECTION_STATUS.md`(익명 집계)에 있다. 보관자가 `status` 명령으로 다시 만든다.

## 1. 이 세션이 한 것과 하지 않은 것

- 한 것: 기존 계획(v68·v69·v70 `NEW_DATA_PLAN.md`, v76 `COLLECTION_REQUEST.md`)과 v68·v70 도구를 읽었다. 그리고 다음을 만들었다: 명세(`DATA_SPEC.md`), 역할별 안내·빈 양식(`packets/`), 보관자 도구(`collection_tool.py`)와 합성 검사(`selftest_collection_tool.py`).
- 하지 않은 것: 질의 작성 · 정답 확인 · 동의 받기 · 참여자 연락 · 외부 모델 호출 · 유료 작업 · 커밋·푸시·PR.
- 노출 고지: 이 세션의 에이전트는 개발 기록(실험 메모의 실패 질의 번호 등)을 맥락으로 갖고 있었다. 그래서 질의를 쓰거나 정답을 확인하는 역할에는 쓸 수 없다. 패킷에는 기존 질의 원문·개발 결과·실패 목록·모델 출력·작품별 정답 대조표를 넣지 않았다. 안내문에 예시 질의도 넣지 않았다.

## 2. 역할

| 역할 | 맡는 일 | 조건 |
|---|---|---|
| 질의 작성자(여럿) | 기억으로 질의를 쓰고, 다 쓴 뒤 생각한 곡을 적는다 | 한 사람 몫 ≤ 20%는 본 수집 완료 시점 누적 기준(시범 3명 단계는 넘음, `DATA_SPEC.md` §7). 이번 개선 작업·평가 자료를 보지 않은 사람이 좋다. 본 사람도 받되 자기 보고로 표시한다 |
| 정답 확인자(1명 이상) | 작성자의 곡을 코퍼스 메타로 확인하고, 코퍼스 안팎·잘못된 단서·모호함을 기록한다 | 작성자와 다른 사람. 검색 결과를 보지 않는다 |
| 보관자(1명) | 원본 보존, salt, 분할, 봉인, 철회 처리, 익명 집계 | **현재 검색 정책 개발에 참여하지 않는 사람.** 개발자가 맡으면 한계로 기록한다 |
| PM | 역할 지정, 동의 안내 빈칸(문의처·기한·보상), 학교 규정 확인, 봉인 전 채택 기준 고정 | — |

한 사람이 여러 역할을 맡을 때의 한계:

- **작성자 = 확인자**: 독립 확인이 아니다(`self_checked`로 따로 센다).
- **보관자 = 개발자**: 봉인 내용을 아는 사람이 정책을 고를 수 있다. 봉인 평가 결과는 "보관자 비독립"이라고 적는다.
- **작성자 = 개발자**: 시스템이 잘하는 것과 못하는 것을 알고 쓴 질의다(`writer_is_developer`·`writer_exposed`로 하위 집계).

## 3. 흐름

| 순서 | 누가 | 무엇 |
|---|---|---|
| 1 | PM | 역할 지정 · 동의 안내 빈칸 채움 · 보관자에게 이 폴더 전달 |
| 2 | 보관자 | `init` → `commit-salt` → 코퍼스 메타 → 작성자별 패킷(`make-writer-packet`) |
| 3 | 보관자 | 패킷 전달(`packets/writer/` 안내 + 빈 표 + 동의 안내만) |
| 4 | 작성자 | 기억으로 질의 → 쓴 직후 기억 방식 열 → 다 쓴 뒤 생각한 곡 |
| 5 | 보관자 | `intake` → `check`(형식만 되물음) |
| 6 | 확인자 | 작성자별 확인 표 + 코퍼스 메타로 정답 확인 |
| 7 | 보관자 | `intake --kind checker` → `split` → `export` → `status` → `verify` |
| 8 | 보관자 → 개발 | `policy_dev` 내보내기 + `COLLECTION_STATUS.md`만 |
| 9 | PM | 비교 구성·채택 기준 고정 → 보관자가 `criteria_fixed` · `sealed_opened`(1회) |

자세한 명령은 `packets/keeper/KEEPER_PROCEDURE.md`에 있다.

## 4. 갈래 — 일반 분포와 집중 진단을 섞지 않는다

| 갈래 | 작성 | 지표 |
|---|---|---|
| `general` | 유형 할당 없음. 떠올린 그대로 | **채택 판단은 여기서만.** 코퍼스 내 Hit@1/5/10·MRR@10(신뢰구간·갈린 질의 수) |
| `diag_work` | 작품(드라마·예능·영화 등)을 떠올리되 작품명을 쓰지 않음 | 진단 표만. `general`에 합치지 않는다 |
| `diag_sound` | 소리 단서 위주 | 진단 표만 |

- 진단 갈래는 그 작성자의 `general` 묶음을 받은 **뒤에만** 부탁한다. 진단 갈래를 먼저 쓰면 일반 갈래 문장이 그쪽으로 기운다.
- 앨범 소개(v76/v77)·표지용 진단 갈래는 만들지 않는다(v76 `COLLECTION_REQUEST.md` §5). 개선안에 맞춘 유형 요청은 하지 않는다.
- 진단 갈래 안내는 `WRITER_GUIDE.md`에 아래 한 단락만 더해 보낸다. 보관자가 패킷을 만들 때 `--track diag_work` 또는 `diag_sound`로 만든다.
  - `diag_work`: "드라마·영화·예능·광고 등에서 들은 노래를 떠올려, 작품 이름은 쓰지 말고 장면·인물·상황으로 써 주세요. 작품을 잘못 기억했을 수도 있으면 기억대로 씁니다."
  - `diag_sound`: "악기·목소리·소리처럼 귀에 남은 것을 중심으로 써 주세요. 가사나 상황을 덧붙여도 됩니다."

## 6. 개발 세션에 넘기는 것

진행률·자료 범위·제약만 넘긴다(`COLLECTION_STATUS.md`). 봉인 자료의 질의·정답·질의별 결과는 넘기지 않는다. policy_dev는 보관자가 내보낸 파일로만 받는다. 원문은 공개 저장소에 커밋하지 않는다(동의 안내 약속).
