읽는 법:

- **늘어난 것은 경로 검색이다.** 질의 분석과 리랭킹은 952곡 때와 같다(리랭킹은 채점 후보 20개로 정해진다).
- 경로 안에서는 텍스트 DB 조회가 127 → 430~460ms로 가장 많이 늘었다. 하이브리드 점수를 코드에서 합산하려고
  dense·sparse를 **컬렉션 전체 페이로드와 함께** 두 번 훑기 때문에(`qdrant_backend.py`의 `HYBRID_SCAN_LIMIT`) 곡 수에
  비례한다. 가장 느린 경로는 텍스트(28~35건)와 보컬·편성 단서 경로(22~29건)다.
- 첫 번과 두 번째의 차이(중앙값 +114ms)는 측정 사이 변동으로 본다 — 질의 분석은 오히려 두 번째가 빨랐고 경로·리랭킹이
  함께 느렸다. 한 수치로 말할 때는 **중앙값 약 4.8초, p95 약 5.7초**로 적는다.

## 잴 때 본 것

- 같은 질의("비 오는 날 혼자 듣기 좋은 잔잔한 발라드")의 경로 시간이 dev 측정 직후 서버에서는 929ms, 새로 띄운 서버에서는
  344ms였다. 그래서 새 서버로 dev 57건을 다시 쟀지만 분포는 거의 같았다(경로 중앙값 782 → 884ms). 리허설 질의는 보조
  경로가 적어 dev 평균보다 빠르다. **리허설 한 번의 수치로 dev 분포를 말하지 않는다.**
- 기동 직후 · 단일 요청 · 동시 요청은 각각 다른 수다. 여기 숫자는 모두 예열 뒤 단일 요청이다. 동시 요청은 재지 않았다.
